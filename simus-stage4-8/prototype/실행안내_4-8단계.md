# 4~8단계 로컬 실행

기존 3단계 서버 준비는 `SERVER_README.md`의 PostgreSQL 01→04→06→05 순서와
환경변수 설정을 따른다. SQLite legacy는 실행하지 않는다. 운영 DB·실제 행사 일정은
자동 생성하지 않는다. 아래 주소는 이 컴퓨터의 로컬 개발 예시다.

```sh
# 터미널 1: 기존 서버, DB 환경변수는 SERVER_README.md에 따라 별도 설정
prototype/.venv/bin/python prototype/server.py --port 8765

# 터미널 2: 새 화면 호스트. upstream은 터미널 1의 주소
python3 prototype/client_gateway.py --port 8780 --upstream http://127.0.0.1:8765 --label '개발 테스트 DB'
```

- 모바일 `http://127.0.0.1:8780/mobile/`
- 관리자 `http://127.0.0.1:8780/admin/`
- Unity Hub에서 `prototype/unity/SIMUSPrototype`을 Unity 6000.3.24f1로 열고
  `Assets/Scenes/NeighborhoodLive.unity` Play. `CityLiveClient.apiBase`를 프록시 주소에 맞춘다.
- Chrome 390px 뷰포트는 검증했지만 실제 휴대폰 접속에는 같은 Wi-Fi,
  개발 프록시 `--host 0.0.0.0`, 올바른 컴퓨터 IP, HTTP 보안 설정이 별도로 필요하다.
  관리자 키와 DB 주소는 브라우저/Unity 프로젝트에 넣지 않는다.

`client_gateway.py`의 `/client-config.json`은 `mode=live`를 내보낸다.
이것은 서버 API 연결 방식이다. `label`에 실제 데이터 출처를 명시한다.
API가 내려가면 프록시는 502를 반환하며 화면에 실패를 표시한다. 모의 NPC
실험은 `python3 prototype/integration/npc_lab.py` 후
`http://127.0.0.1:8790/`에서 **모의 데이터**로 따로 연다.

통합 결과: `integration/검증결과.md`. 서버 변경 제안: `contracts/API.md`.
테스트 DB 시연용 관리자 키는 서버가 생성하는 `prototype/data/admin-key.txt`이며
코드 저장소에 포함하지 않는다. 현재 서버는 정적 화면을 직접 제공하지 않으므로
화면 접속에는 프록시가 필요하다.
