# 관리자 운영 화면 (6단계)

`prototype/client/admin/`만 소유하는 별도 ES module 화면. 개발 프록시로 `/admin/`에 접속한다. `/api/*`는 동일 출처 서버에 전달하고 `/client-config.json`은 `{ "mode": "live" }` 또는 `{ "mode": "mock" }`를 제공해야 한다. 연결 유형 확인 실패 시 운영 버튼을 잠근다. 모의 모드는 상단에 테스트 데이터라고 표시한다. 파일을 직접 열어서는 동작하지 않는다.

## 기존 실제 API 재사용

- `POST /api/admin/login {key}` → HttpOnly 관리자 쿠키. 키는 입력 직후 지우며 localStorage/sessionStorage에 저장하지 않는다.
- `GET /api/config`의 `admin`으로 인증 복원·만료를 확인한다.
- `GET /api/state`로 현재 회차·도시 버전·서버 시각·마감 및 종료 시각을 1초마다 조회한다. 초기 404는 시작된 회차 없음이다.
- `POST /api/admin/start {duration,scale:0.1}`: 10~86400초 정수. 계수 0.1은 임시 연결 시험값이며 전시 운영 설정이 아니다.
- `POST /api/admin/finish {round,confirmed:true}`: 확인 패널의 고정 회차 ID만 전송한다. 패널을 연 뒤 다른 회차로 바뀌면 확인을 취소한다.

`RUNNING + accepting=true`는 접수 중, `RUNNING + accepting=false`는 입력 마감, `CLOSING`은 종료 준비, `FINALIZED`만 결과 공개다. 클라이언트 시각으로 상태를 전환하지 않는다. 연결 끊김 때 마지막 상태임을 표시하고 운영 버튼을 잠근다. 최종 종료는 실제 서버 응답을 확인한다.

## 실패 처리와 한계

시작 API에는 멱등 요청 키가 없다. 타임아웃/네트워크 오류/5xx 때 자동 재전송하지 않는다. 이전 회차 ID만 sessionStorage에 남기고, 서버에 새 회차가 확인될 때까지 시작 버튼을 잠가 중복 생성을 피한다. 서버가 실제로 요청을 받지 않았다면 운영자가 서버 기록으로 확인해야 한다. 이후 해당 브라우저의 `simus-admin-pending-start` 세션 항목을 지우고 새로고침해 잠금을 해제할 수 있다. 확인 없이 해제하면 중복 회차 위험이 있다. 이 항목은 비밀값이 아니다.

수동 종료 실패 후에는 회차 상태를 재조회하며, 서버가 RUNNING으로 확인된 경우 같은 회차에 대해서만 다시 확인·요청할 수 있다. 서버 기존 구현이 반복 종료 확정의 중복 효과를 막는다. 이 UI 자체로 그 보장을 대체하지 않는다.

## 서버 담당자에게 남기는 확장 사항 (서버 파일 수정 없음)

1. 시작 멱등 요청 키와 요청 결과 조회: 응답 손실 후 확실한 재시도 및 복구에 필요하다.
2. 관리자 로그아웃·개별 세션 폐기 API: 현재 없음. UI에 가짜 로그아웃을 넣지 않았다. 현재 세션은 서버 재시작까지 지속한다.
3. 관리자 과거 회차 목록·결과 조회 화면을 위한 목록 API: 특정 회차 state 조회는 기존에 가능하지만 전체 목록 API는 없다.
4. 학과 목록 설정·집계, 알림 채널·중복 발송 방지 상태 API는 없음. 외부 서비스를 연결하지 않았고 통계를 만들어 표시하지 않는다.
5. 자동·수동 종료 기능은 기존 PostgreSQL 서버에 구현되어 있다. 이 화면 구현만으로 DB 동시성·결과 불변성의 실제 검증 완료를 주장하지 않는다.
