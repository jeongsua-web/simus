# SIM:US Unity 맵 시제품 — 2단계

게임 엔진: Unity 6000.3.24f1. 렌더링 방식: Built-in.

## 실행하기

1. 이 폴더의 `Unity에서_열기.command`를 실행합니다. 또는 Unity Hub에서 **Add → Add project from disk**로 `SIMUSPrototype` 폴더를 선택합니다.
2. 최초 실행 시 Unity Editor Software Terms 창이 뜨면 내용을 직접 확인하고 동의 여부를 결정합니다. 현재 이 컴퓨터에서는 해당 동의 창까지 열어 둔 상태이며 자동으로 동의하지 않았습니다.
3. Unity에서 `Assets/Scenes/Neighborhood.unity`를 엽니다.
4. 상단 ▶ Play를 누르면 맵을 둘러볼 수 있습니다. Game 창이 작으면 창을 넓히거나 Game 탭을 최대화합니다.

| 조작 | 동작 |
|---|---|
| 왼쪽 드래그 | 맵을 중심으로 카메라 회전 |
| 오른쪽 또는 가운데 드래그 | 카메라 이동 |
| 휠/트랙패드 스크롤 | 확대·축소 |
| 1 또는 R | 전체 조감도로 복귀 |
| 2 | 위에서 보는 배치도 |
| 화면 상단 Overview / Top view | 위 두 시점 전환 |

화면의 영어 버튼은 카메라 미리보기 조작용입니다. 참여 화면과 선택지는 이후 모바일 연결 단계에서 만듭니다.

## 포함 내용

- 기존 생활권 맵을 FBX로 가져온 장면. 크기는 X 200m / Y 18.25m / Z 200m입니다.
- 중앙 캠퍼스, 식당가, 업무·쇼핑·학습 구역, 공원, 외곽 주거지.
- 메시 725개 및 원본 색을 바탕으로 한 재질 32종. 한글 표지판은 메시로 변환되어 별도 폰트 설치 없이 보입니다.
- 조감도 카메라, 방향 조명, 주변광, 양면 표면 표시.
- 화면을 둘러보기 위한 카메라 조작 기능.

지도 안의 인물과 금색 번호는 기존 공간 모형의 정적 표시입니다. NPC 자동 이동, 충돌·내비게이션, 선택 상호작용, 서버·DB 연결, 도시 스탯 변화는 다음 단계 작업입니다.

## 주요 파일

- `SIMUSPrototype/Assets/Scenes/Neighborhood.unity`: 실행할 장면.
- `SIMUSPrototype/Assets/Art/Neighborhood.fbx`: Unity용으로 변환한 모델.
- `SIMUSPrototype/Assets/Art/BlenderMaterials.json`: 원본 재질의 색·금속성·거칠기.
- `SIMUSPrototype/Assets/Materials/`: Unity 재질. 대소문자만 다른 이름도 구분하도록 파일명 끝에 고유값을 붙였습니다.
- `SIMUSPrototype/Assets/Scripts/CityPreviewCamera.cs`: 카메라 조작.
- `SIMUSPrototype/Assets/Editor/SimusSceneBuilder.cs`: 모델 연결·재질·장면 생성 및 검증 도구.
- `Verification/Unity_Overview.png`, `Verification/Unity_Plan.png`: 실제 Unity 카메라의 렌더 결과.
- `Verification/scene-check.txt`: 가져온 맵의 크기·구성 검사 결과.

Blender 원본 `outputs/district_prototype/SIMUS_Neighborhood_Prototype.blend`와 기존 GLB는 보존했습니다. Blender의 촬영용 카메라·조명·배경은 FBX에 넣지 않고 Unity에 맞춰 별도로 구성했습니다. 조명과 색 표현이 달라 Blender 렌더 이미지와 완전히 동일하지는 않습니다.

## 맵을 수정한 뒤 갱신할 때

`export_map.py`는 기존 Blender 원본을 읽어 Unity의 FBX와 재질 정보를 다시 내보내는 도구입니다. Unity에서 맵을 편집한 내용을 Blender로 역전송하지는 않습니다.

Unity 상단 **SIMUS → Create preview scene**은 미리보기 장면을 다시 생성합니다. 현재 `Neighborhood.unity`의 직접 편집 내용은 교체되므로, 수동으로 수정한 장면은 별도 이름으로 저장한 뒤 실행하세요. **Capture preview images**는 현재 맵의 미리보기를 갱신합니다.

다음 작업은 3단계의 서버·DB 구현입니다. 모바일에서 선택한 결과를 저장하고, 이후 Unity가 같은 도시 상태를 읽도록 연결합니다.

## 확인한 내용

2026-09-22, 설치된 Unity 6000.3.24f1에서 가져오기와 스크립트·셰이더 컴파일을 실행했습니다. 맵 경계 200×18.25×200m, 메시 렌더러 725개, 서로 구분되는 재질 매핑 32개를 확인했습니다. 실제 카메라로 조감도·배치도를 렌더해 원본과 배치·글자 방향을 대조했습니다.

Play 모드에서 100회 편집기 갱신 동안 실행한 뒤 조감도·배치도 전환과 초기화를 검사해 통과했습니다. 이 검사는 전시 운영 성능이나 모바일 연결 검증을 의미하지 않습니다.

참고: [Unity 공식 모델 가져오기 안내](https://docs.unity3d.com/6000.0/Documentation/Manual/ImportingModelFiles.html), [Unity 공식 셰이더 표면 방향 안내](https://docs.unity3d.com/2022.3/Documentation/Manual/SL-ShaderSemantics.html).

## 4~8단계 작업 장면 (2026-09-24)

기존 `Neighborhood.unity`는 2단계 미리보기로 보존한다. 실제 도시 표시 작업은
`Assets/Scenes/NeighborhoodLive.unity`를 열어 Play한다. `CityLiveClient.apiBase`는
동일 컴퓨터의 개발 프록시 `http://127.0.0.1:8780`으로 설정되어 있다. 다른 포트를 쓰면
작업 장면의 컴포넌트에서 주소를 바꾼다. 개발 프록시와 실제 PostgreSQL 서버를
먼저 실행해야 한다. 실제 서버가 실패하면 OFFLINE과 마지막 정상 상태가 표시되고
모의 성공으로 바뀌지 않는다.

HUD의 LIVE API는 공개 `/api/state`만 조회한다. 정상일 때 0.5초 폴링하며
회차 ID·버전·서버 시각과 행복도/치안/청결도/오염도를 표시한다.
같은 회차의 낮은 버전, 이전 시작 회차, 한 번 떠난 회차의 늦은 응답을 버린다.
FINALIZED가 되면 미리보기 NPC 이동을 멈춘다. 캡슐 3개는 이름에
`PREVIEW NPC — not a participant`가 명시되어 있으며 실제 참여자 NPC가 아니다.
보행로 경로는 Restaurant pedestrian lane 메시를 34개 지점에서 raycast 검증한
X=-64, Z=12..45 구간이다. 속도 2m/s. 자세한 결과는 `Verification/path-validation.txt`.

안개 오염 25 이상, 청결 경고 35 미만, 치안 경고 35 미만, 행복 지표 65 이상은
`CityLife` 컴포넌트의 Inspector 설정값이다. 모두 **시제품 임시 연출 기준**이며
전시 규칙이 확정된 값은 아니다. 실제 참여자 NPC 식별·위치/경로 API가 아직 없어
이 장면의 NPC를 모바일 본인 NPC와 동기화했다고 판단하지 않는다.

검증: `Verification/stage-play.txt`는 mock 주입 Play 동작, `live-http.txt`는
전용 테스트 PostgreSQL을 읽은 실제 Play 연결, `latency.txt`는 로컬 루프백
선택 제출에서 Unity 감지까지의 측정이다. 실전 전시 네트워크·기기 시험은 남아 있다.
