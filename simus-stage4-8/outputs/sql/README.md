# SIM:US 시제품 SQL

## 파일과 실행 순서

1. `01_schema.sql`: 테이블·키·제약조건·성향 판정 함수·도시 조회 뷰 생성.
2. `02_demo_seed.sql`: 테스트용 회차 1개, 관람객 2명, 지역 1개, 상황 1개, 선택지 2개 등록.
3. `03_verify.sql`: 테스트 데이터에서 제약조건 검증. 테스트 변경은 모두 롤백.

PostgreSQL 18.3의 별도 임시 DB에서 1→2→3 순서로 실행 검증했다. 실제 운영 DB는 만들지 않았다.

새 PostgreSQL DB를 생성한 다음 이 폴더에서 아래 순서로 실행한다. 접속 주소는 사용할 DB 주소로 지정하며 비밀번호를 파일에 적지 않는다.

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f 01_schema.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f 02_demo_seed.sql
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 -f 03_verify.sql
```

DB 관리 도구의 SQL 편집기에서 파일별 전체 내용을 순서대로 실행해도 된다. 01·02는 한 번만 실행한다. 재실행 시 기존 데이터를 삭제하지 않고 오류로 중단한다. 03은 테스트 데이터를 수정하지 않은 상태에서 재실행할 수 있다. 운영 DB에는 02·03을 실행하지 않는다.

## 포함 범위

핵심 데이터의 테이블 생성, FK·UNIQUE·범위 제약, 도시 초기값, 개인 초기값, 성향 판정, 성공 기록과 결과의 UPDATE/DELETE 차단을 포함한다. 세부 관계를 안전하게 구분하기 위해 17개 테이블을 사용했다. 학과·NPC·알림은 제외했다.

샘플 회차는 DRAFT로 남겨 둔다. 시각은 시드 실행 시각 + 1일이며 나중에 시작하려면 DRAFT 상태에서 예정 종료 시각을 다시 설정한다. 보정 계수 0.1은 연결 확인용 예시다. 관리자 행은 로그인 기능이 아니며 인증 토큰도 만들지 않는다.

선택 1의 예상 변화: 개인 (+1,+1), 도시 행복도 +0.3, 청결도 +0.5, 치안 0. 오염 변화 요청은 -0.5이나 초기 오염이 0이므로 실제 반영은 0이다. 선택 2는 모두 변화 없음. 이 결과 계산은 다음 서버 구현 단계에서 구현한다.

## 확인한 항목

- 테이블 생성과 샘플 데이터 삽입 성공.
- 도시 50/50/50, 지역 0, 두 관람객의 개인 점수 0/0.
- 성향 경계값과 9개 조합.
- 동일 상황 중복 기록 거부, 존재하지 않는 선택지 FK 거부.
- 성공 원장 수정 거부, 도시 수치 0~100 제약.
- 트랜잭션 실패 시 앞선 변경 롤백.
- 동시 진행 회차 한 개 제한.

## 다음 서버 구현에서 반드시 처리할 부분

이 SQL은 데이터 구조다. 다음 동작이 자동으로 구현된 것은 아니다.

- 익명 재접속 인증, 관리자 인증, 본인 결과 조회 권한.
- 참여 등록 시 개인 누적 행 생성, 회차 시작 전 콘텐츠·지역 준비 상태 검증.
- 같은 요청 키의 재전송에 기존 응답 반환, 다른 본문 충돌 처리.
- 선택 저장과 개인·도시·지역 갱신을 하나의 트랜잭션으로 실행.
- 회차 시작 이후 설정·콘텐츠 고정, 상태 전이 검사, 종료 이후 상태 갱신 금지.
- 자동 마감 시각의 엄격한 비교, 수동 종료 승인, 종료 중 미완료 요청 취소 및 커밋 경합 제어.
- 도시·지역·개인 결과를 함께 생성하고 FINALIZED로 전환. 미응답자 결과도 생성.
- 종료 전 개인 점수·선택지 영향값 비공개, 종료 후 본인 결과만 공개.
- 최소 권한의 서버용 DB 역할 설정. 테이블 소유자 계정을 웹 클라이언트에 제공하지 않는다.

위 동작은 현재 테이블에 직접 INSERT/UPDATE하면 우회될 수 있으므로, 실제 운영 전에 서버의 처리 경로와 권한을 함께 구현해야 한다. 현재 검증은 스키마 검증이며 실제 동시 제출·종료 동시성·전체 서비스 검증은 아니다.
