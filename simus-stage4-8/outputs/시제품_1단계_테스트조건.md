# SIM:US 시제품 1단계 — 테스트 조건

작성일: 2026-09-22

상태: 검토용 초안. 상황 수는 사용자에게 선택을 요청했으며, 아래는 상황 1개 기준 권장안이다. 회차 길이·인원·보정 계수는 테스트용 제안값으로, 실제 전시 운영값이 아니다. 이번 단계는 조건 정의이며 Unity·서버 구현이나 실제 기기 검증을 완료한 것은 아니다.

## 1. 첫 테스트 목표

휴대폰에서 선택한 행동이 서버에 한 번만 저장되고, Unity의 공유 도시 수치에 반영되며, 회차 종료 후 본인의 결과를 확인한다.

## 2. 조건

| 항목 | 초안 |
|---|---|
| 게임 엔진 | Unity — 사용자 확정 |
| 맵 | 기존 생활권 맵 `district_prototype/SIMUS_Neighborhood_Prototype.blend`를 바탕으로 연결 |
| 참여자 | 2명, 서로 다른 휴대폰 또는 분리된 브라우저 세션 |
| 관리자 | 1명. 테스트 참여자와 겸할 수 있지만 관리자 권한은 별도로 확인 |
| 접속 | 같은 Wi-Fi에서 휴대폰 2대와 Unity 실행 컴퓨터 연결 |
| 상황 수 | 우선 1개, 선택지 2개 — 사용자 선택 대기 |
| 응답 수 | 한 회차에서 1인당 최대 1회, 두 사람 합계 최대 2회 |
| 회차 길이 | 시작 후 5분. 서버가 시작 시각과 예정 종료 시각을 정함 |
| 자동 마감 | 시작 후 4분 55초부터 신규 선택 접수 거부 |
| 결과 공개 | 시작 후 5분에 종료 처리를 완료한 뒤 공개 |
| 수동 종료 | 관리자 최종 확인 후 즉시 접수 마감, 진행 중 요청 정리 후 결과 확정 |
| 새 회차 | 이전 결과를 보존하고 도시·개인 상태를 초기값으로 새로 시작 |
| 도시 초기값 | 행복도 50 / 치안 50 / 청결도 50 |
| 오염 초기값 | 테스트 지역 1개, 오염도 0%. 전체 오염도는 이 지역의 값과 같음 |
| 개인 초기값 | X=0, Y=0, 진중립 |
| 도시 영향 보정 계수 | 0.1, 회차 시작 전 고정. 연결 검증용이며 참여 규모에 맞춘 최종 조정값은 아님 |
| 참여자 유지 | 익명 재접속 토큰을 브라우저 쿠키로 유지하는 제안. 동일 브라우저 재접속 시 같은 참여자로 복원 |
| 관리자 접근 | 참여자 인증과 구분된 관리자 로그인. 구체적인 인증 구현은 서버 단계에서 결정 |

기존 요구사항의 종료 경계 규칙을 유지한다. 마감 정각에 도착한 신규 요청은 거부한다. 마감 전에 접수되어도 종료까지 저장·갱신을 완료하지 못하면 취소한다. 수동 종료 승인 전에 이미 반영된 선택은 유지한다.

## 3. 상황과 선택지

기존 SQL 예시의 `WASTE` 상황을 사용한다. 화면에 보일 위치는 학교 서쪽 분리배출함 후보 지점으로 한다. 기존 SQL의 지역 이름은 ‘중앙 광장’이므로 실제 연결 단계에서 표시 이름과 맵 위치를 일치시킨다.

**제목: 분리배출함 옆의 쓰레기**

분리배출함 옆에 쓰레기가 흩어져 있습니다. 어떻게 행동할까요?

| 선택 | 행동 | X 변화 | Y 변화 | 행복도 기본값 | 치안 기본값 | 청결도 기본값 | 지역 오염 기본값 |
|---|---|---:|---:|---:|---:|---:|---:|
| A | 공동 분리배출 규칙에 맞춰 쓰레기를 정리한다. | +1 | +1 | +3 | 0 | +5 | -5 |
| B | 쓰레기를 건드리지 않고 지나간다. | 0 | 0 | 0 | 0 | 0 | 0 |

두 선택은 보통 선택이다. 지나간 이유와 피해 의도가 제시되지 않았으므로 B에 악 점수를 부여하지 않는다.

제출 전 안내: “한 번 제출한 선택은 취소하거나 변경할 수 없어요.”

점수와 도시 영향값은 테스트 설계용 정보다. 참여 중 공개 API와 모바일 선택지에 개인 성향 점수·영향값을 포함하지 않는다.

## 4. 예상 결과

도시 실제 반영값은 기본값 × 0.1이다. 개인 성향에는 보정 계수를 적용하지 않는다. 아래는 서로 다른 새 회차에서 비교할 경우의 결과이며, 같은 참여자의 재선택을 허용한다는 뜻이 아니다.

| 두 참여자의 선택 | 행복도 | 치안 | 청결도 | 오염도 | 개인 점수 |
|---|---:|---:|---:|---:|---|
| A / B | 50.3 | 50 | 50.5 | 0% | 참여자 1 (+1,+1), 참여자 2 (0,0) |
| A / A | 50.6 | 50 | 51.0 | 0% | 각각 (+1,+1) |
| B / B | 50 | 50 | 50 | 0% | 각각 (0,0) |

- Unity에는 소수점 한 자리까지 표시해 작은 변화를 확인한다. 저장값 자체를 표시 자릿수에 맞춰 반올림하지 않는다.
- 오염도는 초기값이 0%이므로 A의 감소 요청 -0.5%p가 있어도 실제 값은 0% 아래로 내려가지 않는다.
- X·Y의 중립 구간은 -2~+2다. 따라서 이 테스트에서는 두 참여자 모두 최종 성향이 진중립일 수 있으며 정상이다.
- 성향 차이를 체험하려면 같은 방향으로 점수가 쌓일 수 있는 서로 다른 상황 3개 이상이 필요하다. 성향 판정 경계값을 낮추거나 같은 상황의 중복 응답을 허용하지 않는다.
- 이 한 상황으로 치안 변화, 오염 증가, 9가지 성향 전체, 전시 규모 균형을 검증할 수는 없다. 이후 별도 콘텐츠·시험 데이터로 확인한다.
- 결과 설명에는 “전시 속 선택 경향이며 실제 인격에 대한 평가가 아닙니다”를 포함한다.

## 5. 이후 구현 후 수행할 검증 순서

1. 자동 종료 회차: 두 사람이 각각 참여해 A/B를 제출하고 예상 도시 수치와 개인별 기록을 확인한다.
2. 성공 요청 재전송 및 같은 상황의 다른 선택 제출: 기록·점수·도시 수치가 중복 반영되지 않아야 한다.
3. 새로고침 후 본인의 참여 기록을 복원하고, 종료 전에는 개인 점수와 성향이 조회되지 않아야 한다.
4. 마감 직전·정각·직후의 신규 요청과 자동 종료 후 제출을 구분하여 확인한다. 실제 경계값 시험은 서버 테스트로도 검증한다.
5. 자동 종료 후 개인 결과와 도시 최종 수치를 확인한다. 종료 요청이 반복되어도 결과는 바뀌지 않아야 한다.
6. 별도 새 회차에서 A/A로 공유 도시 누적을 확인한 뒤 관리자 수동 종료를 시험한다. 일반 참여자의 종료 요청은 거부되어야 한다.
7. 이전 회차 결과가 남아 있고 새 회차는 초기값에서 시작하는지, 이전 회차의 늦은 요청이 새 회차에 반영되지 않는지 확인한다.

## 6. 기존 파일과의 관계

- `요구사항.md`의 기본 규칙을 유지한다. 이 문서는 첫 연결 테스트를 위한 구체화 초안이다.
- 기존 SQL 시드의 예상 참여자 수는 20명이며, 예정 종료 시각은 시드 실행 시각 +1일이다. 이 문서의 2명·5분과 다르므로 실제 구현 단계에서 테스트 회차 설정을 맞춘다. 기존 SQL을 변경하거나 실행하지 않았다.
- `prototype/content.py`의 5개 상황과 `prototype/server.py`는 검증 전 초안이다. 이 문서의 조건이 해당 코드에 적용되었다는 의미가 아니다.
- NPC 이동, 모바일 NPC 추적, 학과 통계, 오염 확산, 도시 외형 변화는 첫 연결 테스트 이후 추가한다.
