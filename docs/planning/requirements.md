## 1. 프로젝트 목적과 핵심 경험

관람객이 모바일에서 일상생활 속 행동을 선택하면, 그 선택이 개인 alignment와 도시의 상태에 누적 반영되는 참여형 도시 시뮬레이션을 구현한다.

**관람객의 일상 속 선택이 자신의 성향과 도시의 상태에 누적되고, 시뮬레이션 종료 시 우리가 만든 도시와 나의 모습을 확인한다.**

1. QR 코드로 모바일 참여 화면에 접속한다.
2. 캐릭터 생성 시 소속 학과를 선택하고, 모바일에서 도시를 돌아다니는 본인 NPC를 따라가는 화면을 본다.
   일상 상황의 선택지는 도시 화면 위에 표시하고 행동 하나를 선택한다.
3. 서버가 선택을 저장하고 개인 alignment와 도시 스탯을 갱신한다.
4. 여러 관람객의 선택이 하나의 도시에 누적된다.
5. 예정된 종료 시각에 자동 종료하거나 관리자가 수동 종료하여 최종 결과를 확정한다.
6. 결과 공개 알림을 통해 최종 도시와 자신의 캐릭터·성향을 확인한다.

개인의 선택이 즉시 눈에 띄는 도시 변화를 일으키는 것은 아니다. 도시의 시각적 변화는 누적된 도시 스탯을 기준으로 한다.

## 2. 운영 원칙

| 항목 | 확정 내용 |
|---|---|
| 운영 기간 | 회차별로 지정된 종료 시각에 자동 종료한다. 관리자는 예정 시각 전에도 해당 회차를 수동 종료할 수 있다. |
| 종료 방식 | 자동 종료와 관리자 수동 종료는 동일한 최종 종료 처리를 수행한다. 수동 종료는 일시정지가 아니며 결과 공개도 앞당겨진다. |
| 종료 처리 | 종료 이후 신규 선택 접수와 시뮬레이션의 상태 변화를 중단한다. 결과 조회는 유지한다. |
| 재선택 | 동일 회차에서 동일 관람객은 동일 상황에 한 번만 응답할 수 있으며, 제출한 선택은 취소·변경할 수 없다. 새 회차에서는 다시 참여할 수 있다. |
| 다음 회차 | 운영한다. 종료된 회차의 결과를 보존하고 관리자가 별도의 새 회차를 시작한다. |
| 개인 성향 공개 | 참여 중에는 공개하지 않고 시뮬레이션 종료 후 공개한다. |
| 도시 상태 | 같은 회차에 참여한 관람객의 선택을 해당 회차의 도시 상태에 누적한다. |
| 최종 결과 | 종료 시 도시 상태와 개인 결과를 보존하여 조회할 수 있게 한다. |

### 2.1 선택 접수와 회차 종료 (2026-09-29 사용자 확정)

- 개별 질문에는 응답 시간제한을 두지 않는다. 신규 입장과 선택은 해당 회차 종료 전까지 허용한다.
- 자동 종료는 서버 시각 기준 예정 종료 정각부터 신규 입장·선택을 거부한다. 기존 5초 선마감은 제거한다.
- 수동 종료는 서버 승인 후 신규 입장·선택을 닫는다. 종료 전 입장자나 이미 열린 선택 패널에도 종료 후 응답 유예를 주지 않는다.
- DRAIN 정책으로 이미 처리 중인 DB 작업을 완료 또는 롤백한 뒤 최종 결과를 한 번 확정한다. 이는 종료 후 사용자의 추가 선택 허용을 뜻하지 않으며, HTTP 도착 순간의 미완료 트랜잭션 강제 취소나 물리 커밋 시각 보장을 뜻하지 않는다.
- 반영되지 않은 선택은 개인·도시에 영향을 주지 않는다. 이미 성공한 선택은 유지하고 동일 요청 재조회에도 중복 반영하지 않는다.
- CLOSING에서는 입력을 차단하고 종료 처리 중임을 알린다. FINALIZED 후 도시·NPC·오염 갱신을 중단하고 확정 결과를 조회한다.
- 현재 코드에는 5초 기본값·양수 admission_buffer 제약이 남아 있다. 이 요구사항 반영은 마이그레이션·API·화면·경계 테스트를 포함한 후속 작업이며 구현 완료가 아니다.

### 2.1.1 결과 알림과 다른 기기 조회 (사용자 확정)

- 웹 푸시를 기본 채널로 사용하고 해당 회차의 수신 동의자 전체를 대상으로 한다. 미응답자도 제외하지 않는다. 유효한 구독·권한이 있어야 발송할 수 있다.
- 일반 모바일 브라우저 참여에는 설치를 요구하지 않는다. iPhone 푸시 신청자에게만 홈 화면 추가·실행·알림 허용을 안내한다. 알림을 거절해도 참여할 수 있다.
- 결과 확정 후 발송하며 중복 억제·재시도·실패 기록을 제공한다. 기기의 실제 수신 시각은 보장하지 않는다.
- 다른 기기에서도 본인 결과를 조회할 수 있는 비밀 결과 링크/복구 수단을 제공한다. 공개 참여자 ID만으로 개인 결과를 노출하지 않는다.
- 이메일 추가와 사용자 결과 다운로드 저장은 시간·자원이 남을 때 구현한다. 서버의 확정 결과 보존은 필수다.

### 2.2 새 회차 시작

다음은 회차 간 상태를 섞지 않기 위한 시제품 기본안이다. 도시·개인 성향을 다음 회차에 계승할지는 별도 확정한다.

- 동시에 진행하는 회차는 하나로 제한하고, 관리자가 이전 회차 종료 후 새 회차를 생성·시작한다.
- 새 회차는 행복도·치안·청결도 50, 지역별 오염도 0%, 개인 alignment (0, 0)에서 시작하는 것을 기본안으로 한다.
- 이전 회차의 선택과 결과는 삭제하거나 덮어쓰지 않는다.
- 참여자 식별 정보는 유지할 수 있으나 선택 기록과 alignment는 회차별로 구분한다.
- 모바일과 Unity는 현재 회차를 명시적으로 확인한다. 이전 회차에서 늦게 도착한 요청을 새 회차 선택으로 전환하지 않는다.
- 종료 알림과 결과 링크는 해당 회차를 가리키며, 새 회차가 시작돼도 이전 결과를 조회할 수 있다.

## 3. 구현 단계

- 게임 엔진은 **Unity**를 사용한다.
- Blender에서 만든 맵을 Unity에 연결하며, 모바일·서버·DB의 역할과 기능 요구사항은 유지한다.

| 구분 | 범위 |
|---|---|
| 이번 연결 시제품 | 모바일 선택, 선택 저장, 개인 alignment 계산, 도시 스탯 갱신, Unity 스탯 표시, 자동·관리자 수동 종료 처리, 새 회차 시작, 회차별 최종 성향 조회 |
| 후속 전시 구현 | 오염 확산, 도시 시각화, 종료 알림, 최종 도시·캐릭터 결과 화면, 개인 선택의 즉각적인 시각 효과, 캐릭터 생성 시 학과 선택 및 학과별 통계, 모바일 본인 NPC 추적 도시 화면 |

후속 구현은 중요도가 낮다는 의미가 아니라, 기본 데이터 연결을 검증한 뒤 진행한다는 의미다.

| F25 | 참여 중 모바일에서 본인 NPC를 따라가는 도시 화면을 제공해야 한다. | 후속 구현 | 모바일 참여 화면이 열려 있는 동안 본인 NPC의 이동에 맞춰 카메라가 자동으로 따라가며 주변 도시를 보여준다. |
| F26 | 도시 화면 위에서 행동 선택과 제출 결과를 확인할 수 있어야 한다. | 후속 구현 | 별도 페이지로 이동하지 않고 선택 패널을 열고 닫으며 NPC 추적 화면으로 이어진다. |
| F27 | 모바일과 전시장 화면이 같은 회차의 도시 상태를 표현해야 한다. | 후속 구현 | 동일한 도시·NPC 식별 정보를 사용하고 재접속 시 현재 회차의 본인 NPC와 최신 상태를 복구한다. |

### 4.1 학과 선택과 통계 기본안

- 학과는 자유 입력 대신 관리자가 설정한 목록에서 선택한다. 학과 선택을 원하지 않거나 소속 학과가 없는 관람객도 참여할 수 있다.
- 학과는 캐릭터 생성 시 선택하며 첫 행동 제출 전까지 수정할 수 있는 기본안으로 한다. 첫 제출 후에는 해당 회차의 학과를 고정한다.
- 학과 정보는 회차별 참여 정보에 저장한다. 이후 회차의 학과 선택이 과거 회차 통계를 바꾸지 않는다.
- 학과별 참여 규모가 다르므로 단순 점수 합계로 순위를 매기지 않는다. 기본 비교는 선택 비율과 성향 분포로 한다.
- 선택지별 비율은 해당 학과에서 해당 상황에 응답한 사람 수를 분모로 계산하고, 응답자 수도 함께 표시한다. 응답이 없으면 0%가 아니라 ‘응답 없음’으로 표시한다.
- 성향 분포는 해당 학과에서 유효한 행동을 한 번 이상 제출한 참여자를 기준으로 계산한다. 미응답자는 별도로 표시한다.
- 개인 성향의 사전 노출을 막기 위해 성향 분포는 종료 후에만 공개한다. 일반 관람객용 상세 통계는 해당 집계의 참여자가 5명 이상일 때 공개하는 기본안으로 한다.
- 학과 통계는 참여한 관람객의 게임 내 선택 경향이며 학과 전체 구성원의 인격이나 성향으로 해석하지 않도록 설명한다.
- 실제 표시할 차트와 공개 범위는 통계 화면 설계 단계에서 확정한다.

### 4.2 모바일 본인 NPC 추적 화면

- 모바일의 참여 중 기본 화면은 도시를 돌아다니는 본인 NPC를 자동으로 따라가는 화면으로 구성한다.
- NPC는 자동 이동하는 기본안으로 하며 관람객의 직접 이동 조작은 이번 요구에 포함하지 않는다.
- 본인 NPC를 알아볼 수 있도록 이름표 또는 강조 표시를 제공한다.
- 행동 선택지는 도시 화면 위의 패널로 제공한다. 선택 처리 중에도 도시 화면을 유지하며 완료 후 패널을 닫을 수 있다.
- NPC가 이동하며 도시를 보여주는 기능과, 개별 선택이 즉각 도시 외형을 바꾸는 기능은 구분한다. 도시 외형은 누적된 도시 스탯을 기준으로 표현한다.
- 개인 alignment 점수·성향은 화면과 이름표에서 종료 전 공개하지 않는다. 성향에 따른 캐릭터 외형 공개도 종료 후로 제한한다.
- ‘계속 표시’는 모바일 페이지가 전면에 열려 있는 동안을 뜻한다. 앱 전환·화면 잠금 후 돌아오면 최신 상태와 NPC 추적을 복구한다.
- 회차 종료 시 이동 시뮬레이션을 멈추고 해당 회차의 최종 도시·캐릭터·성향 결과 화면으로 전환한다.
- 모바일 제공 방식(모바일에서 도시 렌더링 또는 서버 화면 전송), 표시 지연 목표와 지원 기기는 연결·성능 실험으로 결정한다. 관람객마다 본인 NPC를 따라가는 시점을 제공해야 한다.

## 5. 개인 alignment 요구사항

| 항목 | 규칙 |
|---|---|
| 구성 | 질서–혼돈, 선–악 두 축으로 구성한다. |
| 계산 | 선택지에 지정된 점수를 개인별로 누적한다. |
| 판정 | 각 축을 세 구간으로 구분하여 총 9가지 성향 중 하나로 판정한다. |
| 참여 규모 보정 | 적용하지 않는다. |
| 공개 시점 | 시뮬레이션 종료 후 공개한다. |
| 최종 결과 | 최종 성향과 그 의미를 설명하는 해석을 제공한다. |

### 5.1 초기값과 선택 점수

- 초기값은 **(0, 0), 진중립**이다.
- 첫 번째 축 X는 양수일수록 질서, 음수일수록 혼돈이다.
- 두 번째 축 Y는 양수일수록 선, 음수일수록 악이다.
- 보통 선택은 관련 축에 **±1**, 중대 선택은 관련 축에 **±2**를 부여한다. 관련 없는 축은 0이다.
- 두 축은 독립적으로 점수를 지정한다. 한 선택이 두 축 모두 또는 하나의 축에만 영향을 줄 수 있다.
- 점수는 정수로 누적하며 상한·하한으로 잘라내지 않는다. 반대 방향의 선택은 기존 점수를 상쇄한다.
- 도시 스탯 영향값과 alignment 점수는 별개로 관리한다. 오염 증가 등 도시 결과만으로 개인 성향 점수를 자동 결정하지 않는다.

### 5.2 선택지 점수 부여 기준

| 판단 대상 | 양수 방향 | 음수 방향 | 0점 기준 |
|---|---|---|---|
| 질서–혼돈 X | 공통 규칙·약속·절차를 존중 | 규칙보다 개인 판단·자율을 우선 | 상황에서 규칙과 자율의 갈등이 드러나지 않음 |
| 선–악 Y | 타인·공동체를 배려하고 피해를 줄임 | 타인에게 줄 피해를 알면서 자신의 이익을 우선 | 배려나 피해 의도를 판단할 근거가 없음 |

질서가 곧 선이거나 혼돈이 곧 악인 것은 아니다. 상황에 제시된 행동의 맥락을 기준으로 선택지마다 (X 변화량, Y 변화량)을 미리 지정한다. 편의를 택했다는 이유만으로 악 점수를 부여하지 않는다.

다음은 점수 작성 예시이며 실제 전시 선택지는 별도로 작성한다.

| 상황 속 행동 예시 | 구분 | X | Y |
|---|---|---|---|
| 공동 분리배출 규칙에 맞춰 쓰레기를 정리한다. | 보통 | +1 | +1 |
| 자신의 시간을 들여 길을 잃은 사람을 돕는다. | 보통 | 0 | +1 |
| 편의를 위해 정해진 절차를 생략하지만 타인 피해 여부는 제시되지 않는다. | 보통 | -1 | 0 |
| 규정의 허점을 이용해 다른 사람의 몫을 의도적으로 독점한다. | 중대 | +2 | -2 |
| 부당한 규칙을 어기고 피해를 입는 사람을 보호한다. | 중대 | -2 | +2 |

### 5.3 최종 성향 판정

누적 점수에 다음 고정 경계값을 적용한다. 보통 선택 한 번만으로 중립을 벗어나지 않도록 하고, 같은 방향의 선택이 반복되면 성향이 드러나도록 설계한다.

| 축 | 음수 구간 | 중립 구간 | 양수 구간 |
|---|---|---|---|
| X | -3 이하: 혼돈 | -2~+2: 중립 | +3 이상: 질서 |
| Y | -3 이하: 악 | -2~+2: 중립 | +3 이상: 선 |

| X 판정 / Y 판정 | 선 | 중립 | 악 |
|---|---|---|---|
| 질서 | 질서 선 | 질서 중립 | 질서 악 |
| 중립 | 중립 선 | 진중립 | 중립 악 |
| 혼돈 | 혼돈 선 | 혼돈 중립 | 혼돈 악 |

- 판정에는 반올림이나 무작위 처리를 사용하지 않는다.
- 미응답자는 (0, 0) 진중립으로 유지하며 결과에 ‘참여한 선택 없음’을 표시한다.
- 결과 해석은 참여자의 실제 인격 평가가 아니라 전시에서 선택한 행동의 경향임을 설명한다.
- 적게 응답한 참여자는 진중립으로 남을 수 있다. 응답 수가 많을수록 중립을 벗어나기 쉬운 고정 누적 방식이며, 결과를 참여자 간 순위로 사용하지 않는다.

## 6. 도시 스탯 요구사항

### 6.1 기본 수치

| 스탯 | 초기값 | 범위 | 기본 영향 규칙 |
|---|---|---|---|
| 행복도 | 50 | 0~100 | 보통 선택 ±3~5, 중대 선택 ±10 |
| 치안 | 50 | 0~100 | 보통 선택 ±3~5, 중대 선택 ±10 |
| 청결도 | 50 | 0~100 | 보통 선택 ±3~5, 중대 선택 ±10 |
| 지역별 오염도 | 0% | 0~100% | 선택에 따른 증감량을 별도로 정의하고 주변 지역으로 확산 |

‘중요 선택’ 구분은 사용하지 않는다. 각 선택지가 영향을 주는 스탯과 증감 방향을 개별 지정하며, 모든 선택이 모든 스탯을 바꿀 필요는 없다.

### 6.2 참여 규모 보정

한 사람의 선택이 도시 전체에 과도한 영향을 주지 않도록 기본 영향값을 보정한다.

**실제 반영값 = 기본 영향값 × 참여 규모 보정 계수**

| 항목 | 규칙 |
|---|---|
| 예상 총 선택 횟수 | 해당 회차의 예상 참여자 수 × 1인당 예상 응답 수 |
| 계수 결정 | 예상 총 선택 횟수와 도시 변화 목표를 기준으로 사전 실험하여 결정한다. |
| 운영 중 변경 | 각 회차 시작 전에 확정하고 해당 회차 운영 중에는 고정한다. |
| 적용 대상 | 행복도·치안·청결도 및 선택에 따른 지역별 오염도 증감 |
| 정밀도 | 소수점 값을 저장하여 작은 영향도 누적되도록 한다. 표시값만 반올림한다. |
| 범위 제한 | 갱신 결과가 범위를 벗어나면 0 또는 100으로 제한한다. |
| 오염 확산 | 선택 영향값 보정과 별도로 확산 규칙을 정한다. |

## 8. 시제품 검증 기준

- 실제 모바일 기기와 전시용 기기를 분리하여 전체 흐름을 확인한다.
- 최소 2명의 관람객이 참여하여 개인 정보는 분리되고 도시 스탯은 누적되는지 확인한다.
- 선택별 예상 계산 결과가 서버에 저장된 결과와 일치해야 한다.
- 정상 연결 상태에서 선택 접수 후 2초 이내 Unity 표시 갱신을 목표로 한다.
- 재선택과 동일 요청 재전송이 중복 반영되지 않아야 한다.
- 테스트용 종료 시각에 자동 종료되는지, 관리자가 예정 시각 전에 수동 종료할 수 있는지 각각 확인한다.
- 두 종료 방식 모두 이후 선택 접수와 도시 상태 갱신이 중단되고 최종 결과가 공개되어야 한다.
- 관리자 권한이 없는 종료 요청은 거부하고, 반복 종료 요청에도 결과가 바뀌지 않아야 한다.
- 종료 전에는 개인 성향이 공개되지 않고 종료 후에는 최종 결과를 조회할 수 있어야 한다.
- alignment 초기값 (0, 0)과 각 축의 -3, -2, +2, +3 경계값 및 9가지 조합을 확인한다.
- 자동 종료 시각 직전·정각·직후 입장/선택을 구분하여 정각부터 신규 접수가 거부되는지 확인한다. 5초 선마감이 없는지도 확인한다.
- 수동 종료 승인 후 신규 접수가 차단되고 DRAIN 정리 후 결과가 확정되는지, 이미 성공한 선택과 재전송 멱등성이 유지되는지 확인한다.
- 예상 참여 규모의 누적 실험을 통해 초반의 소수 선택만으로 도시 스탯이 한계에 도달하지 않는지 확인한다.
- 서로 다른 선택 경향이 도시 상태에 구분되는 결과를 만드는지 확인한다.
- 두 회차를 연속 실행하여 이전 결과 보존, 새 회차 초기 상태, 동일 관람객의 재참여를 확인한다.
- 이전 회차 요청을 재전송해도 새 회차 상태가 변경되지 않아야 한다.

## 9. 구현 전 확정할 세부 설정

### 이번 시제품에 필요한 결정

- 회차 간 도시·개인 alignment 계승 여부(시제품 기본안은 매 회차 초기값으로 시작)
- 테스트용 회차별 자동 종료 시각과 관리자 접근 방식(실제 축제 날짜는 필요하지 않음)
- 참여자 식별 및 재접속 유지 방식
- 실제 상황·선택지 작성 및 확정된 기준에 따른 alignment 점수·도시 스탯 영향값 지정
- 예상 참여자 수, 예상 응답 수, 참여 규모 보정 계수
- 도시의 지역 구분과 전체 오염도 집계 방식

### 후속 전시 구현에 필요한 결정

- 실제 축제 일정과 회차별 시작·종료 날짜 및 시각
- 오염 확산 주기·비율 및 지역 간 연결 관계
- 도시 스탯별 시각적 변화 조건
- 알림 전달 채널과 수신 신청·동의 절차
- 참여 중 NPC 추적 도시 화면과 최종 도시 모습을 모바일에 제공하는 방식, 표시 지연 목표 및 지원 기기
- NPC 자동 이동 규칙과 도시·NPC 상태 동기화 방식
- 캐릭터 구성과 alignment의 관계
- 학과 목록, 소속 수정 규칙 및 학과별 통계 공개 범위(기본안: 첫 제출 후 소속 고정, 상세 집계 5명 이상 공개)
- 종료 결과의 조회 가능 기간

QR 접속만으로 종료 알림을 보낼 수 있는 것은 아니므로, 알림 방식에 맞는 수신 절차를 참여 과정에 포함한다.
