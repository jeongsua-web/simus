# 모바일 경험과 구현 계획

작성: 2026-10-07. 상태: 기존 요구사항과 코드 조사에 기반한 작업 초안.

이 문서는 모바일을 구현할 때 목적, 화면별 역할, 작업 순서, 완료 기준을 함께 확인하는 기준점이다. 기존 확정 사항과 아래의 제안을 구분한다. 제안은 새로운 사용자 확정 결정이 아니며, 코드가 있다는 사실을 전시 인수 완료로 보지 않는다.

## 1. 모바일의 목표

**관람객이 도시 속 자신의 캐릭터를 보며 일상 행동을 선택하고, 회차가 끝나면 함께 만든 도시와 자신의 성향을 확인한다.**

기존 [전체 요구사항](requirements.md)의 핵심 경험을 모바일 관점에서 정리했다. 모바일은 관람객 개인의 참여 창구이며, 전시장 Unity 화면과 같은 회차의 도시를 표현한다.

관람객이 화면에서 알 수 있어야 하는 것은 다음 세 가지다.

1. 지금 어느 회차에 참여했고, 도시에서 누가 내 캐릭터인가.
2. 지금 어떤 상황에서 무엇을 선택할 수 있고, 내 선택이 접수되었는가.
3. 언제 결과를 볼 수 있고, 나중에 어떻게 다시 찾아오는가.

### 기존에 정해진 범위

- QR로 모바일 웹에 접속한다. 일반 참여에 앱 설치를 요구하지 않는다.
- 학과를 선택할 수 있고, 소속을 밝히지 않아도 참여할 수 있다.
- 기본 참여 화면은 자동 이동하는 본인 NPC를 따라가는 도시 화면이다. 직접 이동 조작은 현재 범위에 없다.
- 도시 위 패널에서 상황과 선택지를 보고 제출한다. 같은 회차·상황의 제출은 변경할 수 없다.
- 개인 성향은 회차 결과 확정 후 공개한다. 도시 외형 변화는 누적된 도시 상태에 따른다.
- 전시 콘텐츠는 30개 상황을 대상으로 한다. 상황 수와 실제 접수 가능 여부는 서버 회차 데이터를 따른다.
- 모든 상황에 답해야 결과를 볼 수 있는 것으로 가정하지 않는다. 미응답자는 개인 성향 없이 최종 도시를 확인한다.
- 결과 알림은 선택 사항이고, 거부해도 참여할 수 있다. 다른 기기용 비밀 결과 링크를 제공한다.
- 종료 정각 이후 새 선택을 받지 않는다. 이미 처리 중인 작업 정리와 사용자의 추가 응답 유예는 구분한다.

### 이번 문서의 화면 구성 제안

- 입장 준비, 참여, 결과의 역할을 분리한다. 별도 URL 추가 여부는 구현 시 결정한다.
- 참여 화면의 첫 화면에서 도시·내 캐릭터·상황 열기·진행 상태를 볼 수 있게 한다.
- 학과 설정과 알림 안내가 매번 도시보다 먼저 긴 영역을 차지하지 않도록 정리한다.
- 알림 신청은 참여를 가로막지 않는 보조 동선으로 제공한다.
- 순서대로 선택하는 현재 흐름을 임시 기준으로 유지한다. 위치 도착에 따른 상황 자동 노출은 확정 전 구현하지 않는다.

## 2. 화면과 사용자 흐름

기본 흐름: QR 접속 → 참여 안내·학과 선택 → 도시와 내 NPC → 상황 선택·제출 → 도시 관찰 또는 다음 상황 → 종료 대기 → 개인·도시 결과.

| 화면/상태 | 관람객의 목적 | 필요한 정보와 행동 | 현재 진입점 |
|---|---|---|---|
| 시작 | 무엇을 하는 전시인지 이해 | 짧은 경험 설명, 참여 시작 | `/` |
| 입장 준비 | 본인 참여 준비 | 회차 확인, 학과 선택/선택 안 함, 재선택 불가 안내 | 현재 `/participate` 안에 포함 |
| 참여 | 도시를 보며 선택 | 내 NPC 강조·추적, 도시 상태, 상황 패널, 진행 수, 종료 시각 | `/participate` |
| 제출 중/결과 미확인 | 저장 여부 확인 | 중복 제출 차단, 동일 요청 재확인, 명확한 처리 메시지 | 참여 화면 안 |
| 전체 응답 완료 | 남은 시간을 이해 | 응답 완료 안내, 도시 관찰, 결과 공개 시점 | 참여 화면 안 |
| 회차 없음 | 다음 행동 파악 | 대기 안내, 상태 갱신, 접근 가능한 지난 결과 | `/participate` |
| 종료 처리 중 | 결과 공개 대기 | 입력 차단, 결과 준비 중 안내 | 참여·결과 화면 |
| 결과 확정 | 내 선택의 의미 확인 | 개인 성향·해석, 최종 도시, 본인 캐릭터, 결과 링크 | `/result/[id]` |
| 다른 기기 결과 | 저장한 결과 다시 열기 | 비밀 링크 인증, 읽기 전용 결과, 만료/무효 안내 | `/shared-result` |
| 학과 통계 | 참여 집단의 선택 비교 | 응답 수·선택 비율·성향 분포, 소수 집계 보호 | `/statistics/[id]` |

결과와 통계는 보조 화면이다. 진행 중 개인 성향을 미리 공개하거나, 통계가 참여를 위한 필수 단계가 되지 않게 한다.

## 3. 현재 구현과 목표 사이의 차이

아래 상태는 소스 확인 결과다. 이번 문서 작업에서 서버 실행이나 실기기 검증은 수행하지 않았다.

| ID | 기능 | 현재 구현 근거 | 남은 작업 / 완료 조건 |
|---|---|---|---|
| M01 | 참여 진입·본인 복구 | `page.tsx`, `participate/useParticipation.ts`: 참여자 준비, 회차 입장, 기록 조회 | QR부터 첫 선택까지 실제 휴대폰에서 수행. 새로고침 후 같은 회차·응답 복구 |
| M02 | 학과 선택 | `participate/DepartmentSelector.tsx` | 입장 준비 흐름에 배치. 선택 안 함과 첫 응답 후 수정 제한 검증 |
| M03 | 상황 선택·제출 | `participate/SituationCard.tsx`, `useParticipation.ts`: 선택·제출·진행 수·재확인 | 30개 콘텐츠 탐색, 제출 전 변경 불가 인지, 중복 반영 없음 검증 |
| M04 | 도시·본인 NPC | `participate/CityTrack.tsx`: Canvas 2D, 본인 강조·추적, NPC 조회 | 시험용 도로 좌표와 사각형 건물 표현이 남음. 새 맵·경로·표현 방식 연결 필요 |
| M05 | 도시 위 선택 패널 | `participate/page.tsx`, `participate.module.css`: 접이식 오버레이 | 작은 화면에서 도시와 선택 맥락 유지, 긴 문장·스크롤·패널 열기/닫기 검증 |
| M06 | 연결·회차 복구 | `useParticipation.ts`, `pending.ts`: 주기 조회·온라인 복귀·미확인 요청 보관 | 잠금 복귀·통신 단절·회차 전환 시 기록 혼합과 중복 제출 없음 검증 |
| M07 | 종료와 개인 결과 | `result/[id]/ResultClient.tsx`: 결과 대기·성향·최종 도시 수치·미응답 구분 | 최종 도시 모습과 본인 캐릭터 표현 추가. 종료 경계 동작을 서버와 함께 검증 |
| M08 | 결과 재조회·알림 | `participate/PushOptIn.tsx`, `shared-result/page.tsx`, 결과 링크 발급 UI | 실제 푸시 수신, 홈 화면 앱과 일반 탭의 본인 연결, 링크 만료·복구 동선 검증 |
| M09 | 학과 통계 | `statistics/[id]/StatisticsClient.tsx` | 모바일 가독성과 소수 집계·종료 전 비공개 검증 |
| M10 | 선택 직후 시각 피드백 | 현재 제출 상태 메시지는 있음 | 행동별 연출 정의·연결 필요. 개별 반응과 누적 도시 변화를 혼동하지 않게 표현 |

코드 경로는 모두 `web/src/app/` 기준이다. 특히 M04는 최종 전시 맵 구현으로 간주하지 않는다. M08의 기존 미완료 사항은 [결과 알림 진행 기록](../contracts/result-notification-4b.md)을 따른다.

## 4. 구현 순서와 완료 기준

아래 단계는 작업 순서이며 뒤 단계가 선택 기능이라는 뜻은 아니다. 각 단계 완료 시 변경 파일과 검증 증거를 이 문서의 작업 기록에 추가한다.

### 단계 A — 참여 화면의 역할 정리

- 시작 안내, 입장 준비, 참여 중 주 화면, 종료 대기, 결과의 구성을 정리한다.
- 도시 중심 배치, 상황 패널, 학과·알림 보조 동선을 구현한다.
- 로딩·빈 회차·오류·마감·전체 응답 완료 화면을 같은 상태 규칙으로 구성한다.
- 완료 기준: 각 상태에서 다음 행동을 찾을 수 있고, 참여 주 화면에서 도시와 선택 진입점이 보인다. 긴 콘텐츠에서도 버튼이 가려지지 않는다.

### 단계 B — 선택과 복구 흐름 완성

- 서버 응답을 기준으로 접수 여부와 응답 기록을 표시한다.
- 제출 미확인 상태를 성공이나 실패로 단정하지 않고 같은 요청으로 확인한다.
- 진행 중 화면 복귀, 재접속, 다음 회차 이동을 검증한다.
- 완료 기준: 첫 선택부터 부분 응답·전체 응답·마감까지 기록이 정확하며, 재전송은 한 번만 반영된다. 이전 회차 요청이 새 회차에 반영되지 않는다.

### 단계 C — 새 도시와 캐릭터 연결

- 새 `map_version`, 지역, 30개 상황 배치, NPC 경로를 인계받는다.
- 모바일 도시 표현 방식을 실기기 성능·가독성 평가로 선택한다.
- 모바일과 Unity의 회차·지도·NPC·도시 상태를 대조한다.
- 완료 기준: 새 지도 기준의 본인 NPC 추적과 도시 상태 표현을 양쪽에서 확인한다. 지도 버전이 맞지 않으면 잘못된 위치를 표시하지 않고 대기/오류 상태를 제공한다.
- 새 맵 인계 전에도 A·B는 진행할 수 있다. 지도 시험 데이터는 전시 데이터와 구분한다.

### 단계 D — 결과와 재방문 완성

- 최종 도시·캐릭터·성향 해석을 하나의 결과 경험으로 구성한다.
- 비밀 결과 링크, 알림 동의/거절, 실제 수신과 결과 이동을 검증한다.
- 완료 기준: 응답자·미응답자·미참여자의 결과가 구분되고, 다음 회차가 시작되어도 해당 회차 결과를 정확히 조회한다. iPhone 홈 화면 전환 후에도 본인 결과 접근이 이어진다.

## 5. 전시 인수 체크리스트

미체크는 검증 대기 상태다. 코드 존재만으로 체크하지 않는다.

- [ ] 실제 QR로 Android·iPhone에서 설치 없이 진입하고 첫 선택을 제출한다.
- [ ] 제안 검증 폭 360/390/430 CSS px에서 가로 넘침 없이 상황·선택·제출 상태를 읽는다. 실제 기기와 브라우저 버전을 기록한다.
- [ ] 긴 상황 본문, 글자 확대, 키보드 포커스와 상태 안내를 확인한다.
- [ ] 내 NPC 식별·자동 추적과 패널 열기/닫기 중 도시 표시를 확인한다.
- [ ] 선택 제출 중 연타·네트워크 끊김·재접속에도 응답이 한 번만 반영된다.
- [ ] 화면 잠금 후 복귀 시 현재 회차·응답·NPC 상태가 복구된다.
- [ ] 종료 직전/정각/직후 선택, 수동 종료, 미확인 요청 재조회가 계약대로 동작한다.
- [ ] 종료 전 개인 성향 비공개, 종료 후 확정 결과와 도시/NPC 상태 동결을 확인한다.
- [ ] 미응답자의 성향을 임의로 부여하지 않는다.
- [ ] 다른 기기 링크의 조회·재발급·만료와 알림 허용/거절·수신·클릭을 확인한다.
- [ ] 새 맵 기준으로 모바일과 Unity의 회차·지도·NPC가 일치한다.
- [ ] 실기기 로딩 시간·프레임·발열을 측정하고 채택한 표현 방식의 성능 기준을 기록한다.

## 6. 결정이 필요한 항목

| 항목 | 현재 기준 | 결정 시점 |
|---|---|---|
| 도시와 선택의 비중 | 기존 요구사항의 도시·NPC 중심을 초안 기준으로 사용 | 단계 A 화면 구성 |
| 상황이 나타나는 조건 | 현재 코드는 이전/다음 탐색. 순차/자유 탐색/위치 연동 중 최종 방식 미확정 | 상황 노출 방식 변경 전 |
| 첫 접속에서 안내할 내용과 체험 시간 | 설명 길이·목표 체류 시간 미확정. 30개 전부 응답을 강제하지 않음 | 단계 A 사용성 검토 |
| 캐릭터 준비 | 학과 선택은 존재. 이름·외형 직접 선택을 추가할지는 미확정 | 캐릭터 준비 UI 확장 전 |
| 모바일 도시 표현 | 현 구현은 시험용 Canvas 2D. 최종 2D/3D 등 방식 미확정 | 새 맵 샘플 실측 후 |
| 새 지도와 상황·NPC 연결 | 지도 버전·좌표·경로 미확정 | 단계 C 시작 전 |
| 행동별 피드백·최종 결과 연출 | 문구·이미지·애니메이션 및 필요 자산 미확정 | 단계 C·D |
| 성능 목표 | 대상 기기와 수치 기준 미확정 | 샘플 실측 후 전시 인수 전 |

전시용 맵은 새로 제작한다. 기존 `Neighborhood.fbx`, `neighborhood.glb`, `walkway-v1` 좌표는 새 맵의 확정 기준이 아니다. 저장소에 제작 중 자산이 있더라도 최종 지도 버전·배치·인계 완료를 뜻하지 않는다. [새 맵 인계 문서](../content/new-map-handoff-5a.md)에 따라 확정 값을 연결한다.
