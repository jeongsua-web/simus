# 한국 대학가 도시 설계안 v002 — 승인 대기

이 문서는 Unity **구현 계획**이다. 이번 단계에서는 씬을 만들거나 실행하지 않았고 원본 Blender/FBX, 기존 씬, NPC/카메라/이벤트, 웹/백엔드를 변경하지 않았다. `city_rebuild_v002`는 문서 식별자이며 전시 `map_version`이 아니다. 승인 후에도 실측 문 방향과 Unity FBX 축/원점 검증을 거쳐야 실제 배치를 확정할 수 있다.

## 배치 기준과 재사용

Unity XZ 평면의 단위는 1m다. 계획 외곽은 X −225~195 / Z −245~190, 420×435m다. 이전 202×202m/동일한 80×80m 2×2 구획·도로망·학교 프록시는 채택하지 않았다. 10월 13일 보고서의 FBX 구조, 치수, 모델 프리팹, NPC 1.4m/s, 카메라/빌드 현황 조사만 재사용한다. 개별 FBX 55개 인스턴스와 Campus 14개 건물, 원래 운동장·농구장·테니스장·정원을 기준으로 설계했다. 학교는 기존 156.24×212.186m 크기를 유지하며 남측 정문, 북측 후문, 동측 공원 보행문을 둔다.

학교 기준 이동은 (X,Z)=(0,+65), yaw=0, scale=(1,1,1)이다. 캠퍼스 표면을 최종 Y=0으로 맞추는 adapter는 **UnityY=BlenderZ−0.18**이다. 개별 외부 건물은 source ground Z=0을 UnityY=0에 맞춘다. FBX 변환의 handedness 및 모델 root 원점은 아직 Unity에서 확인하지 않았다. 따라서 `origin_correction=[0,0,0]`은 치수 기준 설계 root이며 실제 imported prefab pivot이 영점이라는 인증이 아니다. 향후 실제 renderer bounds 중심/최저점을 측정하여 child offset을 보정하고 계획 root 위치를 유지한다.

학교 원형의 전체 envelope 네 쌍이 겹치거나 문 앞 틈이 협소했다. 원본은 수정하지 않고 후속 인스턴스 wrapper에서 C00 서관 +3m X, C02 실습관 −4m Z, C08 산학협력관 −4m Z, C09 창업관 +9m X를 계획한다. 나머지 10/14개 동은 기존 상대 위치를 그대로 유지한다. 실제 몸체의 비정형 평면은 일부 AABB 겹침이 거짓양성임이 별도 Blender 조사에서 확인됐지만, 이 계획은 캐노피·계단을 포함한 보수적 envelope와 보행 여유를 우선한다. 운동장과 코트는 이동하지 않는다. 남동측 C09 확장을 위해 부지 경계가 국소적으로 X=90까지 늘어나며 전체를 다시 균등 구획하지 않는다.

학교별 최종 root/범위/델타/실측 문은 `campus-placements.csv`, 55개 외부 건물 중심/회전/치수는 `buildings.csv`, split 대상 메시 이름과 실제 source door glass 위치는 `asset_measurements.json`에 있다. 학교 component의 x/z는 전체 envelope의 중심이고 **실제 배치 anchor는 placement_origin**이다. 이 차이를 구현 시 합쳐 읽어서는 안 된다. `campus-components.csv`는 원본 조사 위치이며 최종 배치 목록이 아니다.

## 도로와 지역 구조

학교 정문 앞 R01은 차도6.5m/양쪽 보도3m의 동서 간선이다. 서쪽에서 비스듬히 들어와 정문 앞을 지나 동쪽에서 꺾인다. R02는 차도6m/보도2.5m의 학교 서측 일반도로이며 남측 주거 안쪽으로 휘어진다. R03/R04는 차도4.5m/보도1.8m, R05는 차도4m/보도1.8m다. R06/R07은 폭3.5m의 저속 배송 골목이며 보행 edge는 옆으로 폭2m를 추가 확보한다. 배송 골목의 폭3.5m는 별도 양방향 자동차 도로라는 주장이 아니며 운영 시 차량 진입 시간 제한과 교행 금지 여부를 승인해야 한다.

좌표별 중심선과 역할은 `roads.csv`, 교차로 위치·접속 도로·계획 모서리 반경은 `layout.json.intersections`에 있다. J01은 실제 4지 교차로, J02~J06은 T형 접속이다. 각 도로 모서리 반경4~8m는 확보해야 할 설계 여유이며 현재 중심선 꼭짓점에 이미 원호 메시가 존재한다는 뜻이 아니다. 승인 후 차량 swept path를 그려 corner arc를 조립하며 필요하면 인접 건물과 보도를 다시 검토한다.

R01 서/동 끝과 R02 북 끝은 계획 외곽의 연결 portal이며 외곽 밖 도로 연속은 모델링 범위 밖 가정이다. R02 남쪽, R03 남쪽 및 R04/R05 막다른 끝은 radius7m 회차공간을 계획한다. R06/R07 배송 끝은 10×10m 소형 회차 pad를 확보한다. 실제 차량 회전 성공은 아직 검증하지 않았다. 상권은 정문 앞 작은 점포 8개와 뒷골목 점포/근린센터/백화점 6개로 구성하며 출입 접근과 불규칙한 사이 틈을 활용한다. 아파트4개는 서북측 배경으로 모으고, 다른 주거는 빌라/주택의 실제 크기를 혼합하여 남측과 서측 골목을 따라 배치한다.

구역별 실면적은 학교34,946.93m², 상권14,586m², 서측주거27,816m², 남측주거39,728.5m², 공원16,714m²다. `density.csv`는 해당 구역 내 모든 건물을 포함한 보수적 envelope 점유율을 기록한다. 학교20.34%, 상권27.66%, 서측주거17.53%, 남측주거18.40%이며 캐노피·기단·지붕까지 포함한 도식 지표로 실제 법정 건폐율이 아니다. 외곽420×435m 전체를 주거 필지로 나누지 않으며 차도·보도·보행 여유·캠퍼스와 녹지가 포함된다. 이전 4개 균등 구획의 빈 프록시 대신 69개 실제 크기 건물을 배치했지만 고밀도 한국 도시의 건폐율을 재현했다는 주장은 하지 않는다.

공원 휴식공간 PM1=(140,25), PM2=(142,118)는 각각 기존 COZY_NEIGHBORHOOD_PARK/MODERN_MINIMAL_PARK의 실측12×12m envelope를 반영한다. 바닥·벤치·데크를 선택 재사용하고 식재는 예약된 산책로 바깥으로 선택 배치하는 후속 wrapper 계획이다. 전체 모듈 소품이 현재 보행로에 충돌하지 않는다는 검증은 아직 없다.

## 보행·이벤트·카메라

보도는 실제 차도 중심선의 miter offset으로 작성해 폭을 확보했다. 주요 학교 내부 통로와 정문은 폭3m, 개별 접근로는 외부1.8m/학교2.5m, 공원 산책은2.5m다. 운동장·농구장·테니스장·중앙/상부/남측 정원과 건물 envelope를 장애물로 사용하여 접근 경로를 우회했다. 정문–상권, 후문–서측 주거, 동측 보행문–비정형 공원, 상권–남측 주거가 한 네트워크로 연결된다. 실제 passage 높이·경사·턱·물리 충돌은 Unity 미검증이다.

외부 `entrance`는 source -Z 방향의 계획 proxy이고 실제 문 메시와 대응되지 않은 자산은 승인 후 확인해야 한다. 학교 `entrance`는 실측 glass 중심으로서 문의 표면 normal과 threshold walkability를 검증하지 않았고, `approach_anchor`는 전체 envelope 바깥 계획 접근점이다. 접근점에서 문까지 보행 가능을 정적 bounds 검증만으로 인증하지 않는다.

`pedestrian_nodes.csv`/`pedestrian_edges.csv`는 설계 그래프다. 동일 물리 구간의 branch가 그래프에서 중복될 수 있으며 edge 개수는 실제 횡단보도 개수가 아니다. 차도와 유한폭 경계가 만나는 부분만 나누어 `crossing_roads`를 부여했다. `crossings.csv`와 `layout.json.crossing_facilities`는 17개 물리 횡단시설/영역 예약을 구분한다. 각 시설은 center/roads/width와 corridor별 실제 endpoints 및 covered edge IDs를 포함한다. 교차로 6곳은 복수 횡단팔을 포함한 차량통제 보행영역, 정문은 일반 횡단시설, 회차공간은 저속 보행우선 운영안, 경계 3곳은 범위 밖 도로연속에 필요한 보행 연결 예약이다. 그래프 조각 중복을 새로운 횡단보도로 추가 설치하는 계획이 아니다. XC_J01~XC_J06의 교차로 안쪽 사선 corridor를 실제 보행 가능 경로로 열려면 **보행 전용 phase에서 교차로로 들어오는 모든 차량을 정지시키는 제어**, 또는 모든 충돌 차류에 동일하게 적용되는 명확한 차량 양보/통제를 필수 구현 게이트로 둔다. 일반 방향별 차량 신호만으로 이 corridor의 보행 안전을 통과 처리해서는 안 된다. 차량 시스템을 이번 설계 단계에 구현하거나 NPC 이벤트 로직에 신호 제어를 넣지 않는다. 신호·우선권·차량통제 및 실제 표식은 후속 승인/검증 대상이고, 교차로 차량 통제와 curb ramps를 설치하기 전 일반 보도로 취급해서는 안 된다.

NPC_A/B/C는 실제 인접 edge로 연결된 학교–상권, 공원 순환, 후문–주거 경로 후보다. 전체 왕복시간이 90초 이내여야 한다는 조건은 추가하지 않는다. **기존 최대 이벤트 대기시간90초를 그대로 유지하며 이벤트 로직을 수정하지 않는다.** 후보 장소 EC01~EC05는 확정 30개 이벤트 위치가 아니며 기존/새 회차 데이터에 기록하지 않는다.

아파트 높이37.6~49.6m 때문에 기존 followPitch28.85°의 이론 가림 길이는 약68~90m다. 학교 정문과 공원 휴식장소 앞에는 고층을 두지 않았지만 실제 camera yaw/near/far/추적/가림 처리는 미검증이다. 카메라 기능은 변경하지 않고 승인 후 기존 전체/탑뷰/추적 모드에서 실제 이미지로 확인한다.

## 승인 이후 단계별 구현 게이트

1. 현재 원본 씬과 빌드 설정을 보존하고 별도 신규 scene/prefab 폴더를 만든다. 활성 빌드 장면은 `CompletedMapNpcFollow.unity`; 기존 자동 빌더를 호출하면 씬/빌드 목록을 다시 쓸 수 있으므로 이 설계의 조립 경로로 사용하지 않는다.
2. 기존 개별 FBX를 모델 Prefab으로 로드해 Unity imported renderer bounds/재질/축/root/scale를 측정한다. 별도 authored `.prefab`은 현재 발견되지 않았다. 실제 bounds가 표와 달라지면 배치·정적 검사·QA를 먼저 다시 수행한다. 원본 Blend/FBX를 재저장하지 않는다.
3. Campus 전체는 wrapper에 넣되 C00/C02/C08/C09의 이름 목록에 대응하는 몸체·지붕·창문·기단·문·캐노피·계단·parapet를 instance-only child root로 묶어 이동한다. 메시와 문이 빠지지 않았는지 count/name을 검사한다. 필요한 경우 승인된 별도 파생 FBX를 새 경로에 만들며 원본을 덮어쓰지 않는다. 코트/운동장/정원은 그대로 유지한다.
4. 새 지면과 도로/보도/횡단/회차공간을 계획 좌표에 조립한다. Campus의 기존 바닥·surface는 재사용하며 중복 외부 지면/도로/collider만 인스턴스별 선택 제외한다. 학교 내부 old road/walk와 새 연결로의 중복·단차를 실제 mesh로 확인한다.
5. 69개 문과 보행 연결을 실측 mesh 기준으로 검토하고 경사로/계단/curb/collider를 설정한다. 1.8~3m 경로 폭, NPC 발높이, 접근점–문 threshold, 교차로와 회차 폭을 Physics 검사한다.
6. 향후 NavMeshSurface에서 차도/건물/코트를 area/obstacle로 구분해 bake한다. 각 주요 구역·69개 접근점 pair에 CalculatePath 완전 경로, 끊김/좁은 통로/불필요한 차도 경유를 검사한다. 문 threshold와 off-mesh/ramp가 승인되지 않으면 통과로 기록하지 않는다. 현재 NPC는 MoveTowards 기반이며 NavMesh로 이미 동작하는 것으로 주장하지 않는다.
7. 기존 NPC/카메라를 유지한 채 별도 계획 시험에서 Play Mode grounding/이동/카메라 가림, 탑뷰/아이소메트릭 가독성, draw calls/LOD/WebGL 목표 기기 성능을 확인한다. 승인된 후속 NPC 경로 통합이 필요하면 별도 작업으로 진행한다. 이벤트 wait90초는 회귀검증하되 로직 변경하지 않는다.
8. 정적/Play/camera/NavMesh/성능 결과를 구분해 보고하고 전시 map_version/30개 상황/최종 경로/경계를 사용자와 확정한다. 그전에는 런타임·백엔드 데이터에 이 설계를 넣지 않는다.

재생성은 `python3 docs/planning/city_rebuild_v002/build_plan.py`, 정적 검사만은 `python3 docs/planning/city_rebuild_v002/check_plan.py`다. 조사 데이터를 영구 `asset_measurements.json`에서 읽고 Unity 및 Blender를 실행하지 않는다. 독립 QA 결과는 root가 관리하는 `qa-review.md`/`qa-results.json`을 함께 읽는다.
