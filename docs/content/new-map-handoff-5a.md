# 5A 새 맵·Blender 자산 인계

2026-10-01 변경: 전시 맵은 새로 제작한다. 기존 `Neighborhood.fbx`·`neighborhood.glb`의 표식 좌표와 보행로는 새 맵의 배치 근거로 사용하지 않는다. 기존 `walkway-v1` NPC 경로도 시험용으로만 유지한다. 새 맵의 콘셉트·크기·구역·제작 일정은 아직 입력받지 않았다.

## 새 맵에서 확정할 값

| 항목 | 인계 값 |
|---|---|
| 지도 식별 | 새 `map_version`과 `.blend` 원본·`.glb` 교환본의 파일명 및 해시 |
| 좌표계 | Unity 월드 `[x,y,z]` 미터, Y 위쪽. Blender 내보내기 축 변환을 샘플 좌표로 확인 |
| 지형 경계 | 실제 보행 가능 범위와 NPC 진입 금지 영역 |
| 상황 배치 | `EXHIBITION_01`~`EXHIBITION_30` 각각의 상호작용점, 접근 경로, 표시 방향, 연결 구역 |
| NPC 이동 | 새 `path_version`, 경유점 배열, 속도, 루프/정지 규칙. 서버·웹·Unity가 같은 회차 스냅샷 사용 |
| 지역 집계 | 상황 위치와 별도로 지역 코드·경계·오염 영향 분배를 결정 |
| 자산 | 9성향 캐릭터, 행복·치안·청결·오염 상태 표현의 파일·원점·크기·성능 정보 |

상황별 배치표는 최소한 `situation_code`, `map_version`, `world_xyz_m`, `facing_degrees`, `approach_path_id`, `region_code`, `asset_key`를 가진다. 제작 중 미확정 값은 빈 값으로 두고, 30행이 모두 확인되기 전에는 새 맵 좌표를 전시 시드에 반영하지 않는다.

## 자산 공통 규격 초안

납품 원본은 `.blend`, 교환본은 `.glb`(glTF 2.0)로 한다. 캐릭터의 원점은 발이 닿는 바닥, 전방은 로컬 +Z, 기본 높이는 1.7m 기준으로 두고 Unity에서 실제 크기를 확인한다. `character_<alignment_code>.glb`의 코드는 API의 9성향 코드와 일치시킨다. 도시 상태 자산은 `city_<stat>_<low|base|high>.glb` 이름을 사용하고 같은 위치에서 상태를 교체할 수 있도록 원점과 크기를 맞춘다. 이 규격은 첫 샘플을 맞추기 위한 초안이며 맵 설계와 모바일 실측 후 예산을 확정한다.

파일별 삼각형 수, 재질 수, 텍스처 해상도, 압축 여부를 기록한다. Android·iPhone 브라우저와 Unity에서 로딩 시간·프레임·발열·지면 접촉을 확인한 뒤 최종 파일과 성능 예산을 승인한다. 저장소에는 현재 새 맵 `.blend`/`.glb`와 최종 캐릭터·도시 상태 자산이 없다.

## 코드·데이터 연결 시점

현재 `db/seed_exhibition.sql`의 `EXHIBITION_CITY`와 `pending-map-v1`은 임시 데이터다. 새 맵의 30개 배치·지역·NPC 경로가 확정되면 새 `map_version`과 새 회차 시드에 반영한다. 이미 시작한 회차의 경로·규칙 스냅샷은 바꾸지 않는다. 웹과 Unity는 같은 새 `map_version`을 수신했을 때만 위치를 표시해야 한다.
