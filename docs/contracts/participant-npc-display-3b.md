# 3B — 모바일 도시·Unity 참여자 NPC 표시 진행 기록

2026-10-01. 3A의 [회차·좌표·시간 계약](participant-npc-api.md)을 두 화면에 연결한 구현이다. 현재는 동작 후보이며 3B의 실기기 인수 전이다.

## 구현

- 모바일 참여 화면: 캔버스 경량 도시에서 본인 NPC를 화면 중앙으로 추적한다. 공개 NPC 목록을 함께 보이며 본인은 녹색, 다른 참여자는 황색으로 구분한다. 선택 패널은 도시 위에서 상황을 하나씩 이동·제출한다. 기존 중복 방지와 새로고침 복원 로직은 유지한다.
- Unity 연결 장면: 기존 임시 캡슐 3개 대신 `/api/sessions/{id}/npcs` 목록의 실제 NPC 캡슐을 생성한다. 각 NPC는 회차 가입 시각·경로·서버 시각으로 위치를 계산한다. 실제 목록을 받기 전에는 기존 미리보기를 보이고, 새 회차로 바뀌면 이전 회차 NPC를 제거한다.
- 두 화면: NPC ID 앞 4자리에서 계산한 X축 차선 간격과 동일한 선형 보간·왕복 경로·종료 동결 시각을 사용한다. 요청 왕복의 중간 시각을 서버 시간 기준으로 삼아 지연에 따른 위치 차이를 줄인다. 단말 벽시계를 사용하지 않는다.

## 현재 판정과 남은 인수

이 구현은 기존 Unity 직선 보행로를 사용하는 **경량 2D 후보**다. 사용자가 요구한 재미·로딩·성능 우선의 최종 모바일 방식을 채택했다는 뜻은 아니다. 동일 자산 조건의 Unity Web/경량 3D/현재 후보를 Android·iPhone에서 비교하고 첫 조작 가능 시간, 10분 프레임·발열, 선택 UI, 백그라운드 복귀, 두 기기 위치 일치를 측정해야 한다. 30상황의 최종 동선/자산은 5A와 합쳐야 한다.

검증: 웹 lint·production build, 격리 PostgreSQL 통합 회귀, 보간·차선 간격·왕복·종료 동결 계산 검사 통과. 브라우저 통합 검사는 두 참여자 ID·패널·390px 캔버스 검사를 추가했지만 Playwright 모듈 미설치로 미실행. Unity Editor 배치 실행은 라이선스 클라이언트 연결 실패로 Play 결과를 얻지 못했다. 대신 Unity에 포함된 Roslyn C# 컴파일러와 UnityEngine 참조 DLL로 `NpcCrowdPoller.cs`·`NeighborhoodLife.cs`를 별도 컴파일해 통과했다(테스트용 CityStatePoller 스텁 사용). Editor의 전체 프로젝트 컴파일 통과를 대신하지는 않는다. 실제 휴대폰/Unity 화면 동기화·500명 밀도 성능은 미검증이다. 3B는 **구현 진행, 인수 미완료**로 기록한다.
