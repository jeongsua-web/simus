# NPC events

The participant event API and choice occurrence contract are specified in web/API.md, section “NPC event cycle”. Migration 011 stores durable waiting clocks, guidance and occurrences. Choices update the existing city, region and alignment ledgers atomically with completion. Ticks and submissions share session locks; database constraints additionally enforce one active occurrence per participant and one choice per occurrence.

Only an actual server-computed place entry creates an occurrence. An eligible entry always selects one unanswered playable event, including when several events share the place. There is no probability gate and no 90-second forced event. Unlocated content and unfinished scenes remain inactive. At 60 seconds, guidance chooses the nearest reachable eligible place outside the current occupied place. The 90-second overdue flag is diagnostic only.

Phase 1's ordered-polyline entry scan, durable `location_occupancy`, `location_evaluated_at`, `entry_seq` and consumed entry are reused from commit `7ac43f0`. The scan covers travel between ticker/poll samples, stops at the earliest eligible entry, and uses distance along the correct map's pedestrian graph. No Unity collider or client coordinate authorizes an occurrence. An active occurrence pauses movement; completing its choice uses the existing score transaction and resumes motion. Reconnects, process restarts, staying inside a place and duplicate requests cannot consume a second event in the same visit. Exiting and reentering permits another unanswered event.

Release ports Phase 1's schema as **018** because its historical 016 number is already occupied by the immutable safe-glasses migration on this branch. Apply only after approval, before deploying this server. The historical `DEADLINE` value remains readable; new occurrences use `LOCATION` exclusively. `deadline_at` is null; `guidance_at` is waiting_since + 60 seconds.

The Phase 2 manifest preserves all eight Phase 1 coordinates/place IDs/radii exactly, and prepares four additional playable mappings (12 total). Eighteen scenes remain blocked; their graph candidates are evidence, not active placements. See [the full report](../placement/phase2/implementation-report.md). Both the old v002 and Phase 1 graph versions are retained separately. Exhibition approval remains false; Neighborhood coordinates are not reused.
