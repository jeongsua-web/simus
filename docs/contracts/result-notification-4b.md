# 4B — 미응답 결과·타기기 링크·웹 푸시 진행 기록

2026-10-01. 4B의 서버/웹 연결 구현이며 실기기 알림 인수 전이다.

- 회차에 입장하고 선택하지 않은 참여자는 종료 후 `NO_RESPONSE`로 조회한다. 개인 성향 점수는 표시하지 않고 최종 도시만 보여준다. 응답자는 `SCORED`, 가입 기록이 없으면 `NOT_JOINED`다. 회차 결과 확정 전 조회는 거부한다. 기존 EXCLUDE/INCLUDE 회차 규칙 및 저장된 결과는 바꾸지 않는다.
- 본인 쿠키로 `POST /api/sessions/{id}/result-link`를 호출하면 회차별 256비트 비밀 링크가 발급된다. 서버에는 SHA-256 해시만 저장한다. 링크는 30일 후 만료되며 재발급하면 이전 링크가 무효다. URL의 `#` 뒤에 자격을 넣어 서버 요청 경로·일반 Referer에 싣지 않는다. 공유 화면은 자격을 POST 본문으로 전송하고 읽기 전용 결과만 표시한다. 링크를 가진 사람은 결과를 읽을 수 있으므로 화면에서 이를 알린다.
- `POST /api/sessions/{id}/push-subscription`은 회차 가입자의 푸시 구독을 명시적으로 저장한다. `DELETE`로 해당 회차의 동의를 철회한다. 브라우저 권한 요청은 사용자가 버튼을 누를 때만 시작한다. iPhone은 홈 화면 앱에서 신청하도록 안내한다. 구독은 회차별이며 결과 확정 트랜잭션에서 유효 구독마다 발송 작업을 1개씩 만든다. 0응답자를 제외하지 않는다.
- 운영 스케줄러의 `POST /api/internal/sessions/reconcile`은 회차 종료를 조정한 뒤 준비된 푸시 작업을 최대 20개 발송한다. `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`(외부에서 유효한 `mailto:` 또는 HTTPS 연락처)를 **같은 영구 키 쌍**으로 서버에 설정해야 구독 버튼이 활성화된다. `web-push`를 사용하고, 서비스 워커는 알림을 표시해 해당 회차 결과 URL을 연다. 푸시 페이로드에는 개인 점수나 비밀 결과 링크를 넣지 않는다.

웹 lint·production build와 격리 PostgreSQL 회귀 통과. 회귀에서 무응답/응답자 분리, 링크 인증·교체·만료·종료 전 비공개, 비가입 구독 거부, 의심스러운 푸시 주소 거부, 0응답자 포함 작업 생성·철회를 확인했다. 브라우저 테스트는 Playwright 설정이 없어 미실행이다.

**미완료/인수 조건:** 실제 HTTPS Android/iPhone 홈 화면 앱에서 구독·수신·알림 클릭을 확인한다. iPhone 일반 탭과 홈 화면 앱의 쿠키가 분리될 때 동일 본인으로 연결하는 절차가 아직 없다. 현재 결과 알림은 해당 기기의 쿠키로 결과를 여므로 이 경우 알림 클릭 후 본인 결과에 접근하지 못할 수 있다. 다른 기기용 비밀 링크는 별도 제공된다. 운영 VAPID 키·스케줄러 설정 및 실제 500명 발송 처리량·재시도/중복 전달 측정도 필요하다. 비밀 링크 읽기 API의 배포 계층 요청 제한 설정도 남았다. 따라서 **4B 인수 완료 아님**.
