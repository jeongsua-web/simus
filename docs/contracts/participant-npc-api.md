# 3A — 회차 입장·NPC 공유 계약 v1

2026-09-29 구현. 3B 모바일/Unity 연결 기준. 서버 구현과 화면·실기기 인수는 구분한다.

## API

먼저 `POST /api/participants`로 기존 익명 쿠키를 준비한다.
모든 응답은 `Cache-Control: no-store`, 오류는 기존 `{error:{code,message}}` 규격이다.

| 요청 | 권한 | 동작 |
|---|---|---|
| `POST /api/sessions/{id}/join` | 본인 쿠키·동일 출처 | 선택 전 회차 가입 및 점수 0 초기화. 최초 201, 재요청 200·`replayed:true` |
| `GET /api/sessions/{id}/npc` | 본인 쿠키 | 본인 NPC 한 개. 미가입 404, 인증 없음 401 |
| `GET /api/sessions/{id}/npcs` | 공개 | 해당 회차 NPC 목록. 참여자 ID·학과·점수·응답·자격 미포함 |

세 API는 아래 공통 응답을 사용하며 join만 `replayed`가 추가된다.

```json
{
  "session_id": "15000000-0000-0000-0000-000000000001",
  "status": "RUNNING",
  "server_time": "2026-10-04T03:00:10.000Z",
  "freeze_at": "2026-10-04T04:00:00.000Z",
  "motion_time": "2026-10-04T03:00:10.000Z",
  "frozen": false,
  "npcs": [{
    "npc_id": "45000000-0000-0000-0000-000000000001",
    "epoch": "2026-10-04T03:00:00.000Z",
    "motion": {
      "map_version": "neighborhood-v1",
      "path_version": "walkway-v1",
      "points": [[-64,1.4,12],[-64,1.4,45]],
      "speed_mps": 1.4,
      "loop": true
    }
  }]
}
```

## 좌표·시간·보간

- Unity 기존 월드 좌표, 단위 m, Y 위쪽. `points`는 `[x,y,z]`. 현재 y=1.4는 기존 미리보기 캐릭터 중심 높이다. 다른 자산의 발 원점/높이 보정은 렌더러가 담당한다.
- `walkway-v1`은 기존 NeighborhoodIntegration의 검증용 직선 보행 구간 왕복이다. 최종 30상황 동선은 3B/5A에서 별도 버전으로 확장한다. 모든 NPC가 같은 경로를 쓰므로 군중 겹침 처리는 3B 과제다.
- 경로 마지막 점에서 첫 점으로 돌아가는 선분을 포함한다. 전체 길이 L, 경과 시간 t=`max(0,(motion_time-epoch)/1000)`초, 이동 거리 d=`(t*speed_mps) % L`. 선분 길이를 순서대로 빼고 남은 거리/해당 선분 길이로 선형 보간한다. 중심선 기준 예시의 10초 위치는 `[-64,1.4,26]`이다. 실제 NPC 표시 위치는 아래 차선 간격을 더한다.
- 서버는 PostgreSQL 시각을 사용한다. 클라이언트는 응답 수신 뒤 단조 시계 경과를 server_time에 더해 보간하되 freeze_at을 넘지 않는다. 네트워크 지연은 왕복 시간으로 추정하고, 백그라운드 복귀 시 재조회한다. 단말 벽시계를 기준으로 경과 시간을 누적하지 않는다.
- `freeze_at=min(scheduled_end_at,end_requested_at)`이며 end_requested_at이 없으면 예정 종료 시각이다. 선택의 기존 5초 선마감 시각은 NPC 정지 시각이 아니다. 스케줄러가 늦어도 예정 종료 정각에 정지한다. 수동 종료는 저장된 종료 요청 시각에 정지한다.
- `motion_time=min(server_time,freeze_at)`. CLOSING→FINALIZED 및 서버 재시작 뒤에도 경로·epoch·freeze_at을 유지한다. 네트워크 단절 중 수동 종료를 즉시 알 수는 없으므로 재연결 시 서버 동결 위치로 보정한다.

## 가입·회차 격리

회차와 참여자의 복합 키가 멱등 키다. 동일 회차 재입장/새로고침에 NPC가 새로 생성되지 않는다. 다른 회차에 입장하면 새 NPC ID·epoch가 부여된다. 클라이언트는 session_id가 달라진 응답을 이전 화면에 합치지 않는다.

신규 입장은 RUNNING이고 시작 이후·예정 종료 전일 때만 허용된다. 선택·종료와 같은 회차 행 잠금으로 직렬화하고, 가입 저장 뒤 종료 시각을 재확인한다. 종료 후 기존 가입자의 join 재요청은 조회로만 성공한다. 미가입자의 종료 후 입장은 409다. DRAFT NPC는 공개하지 않는다.

기존 선택 API의 첫 선택 가입도 유지되며 DB 기본값으로 NPC가 부여된다. 모바일 참여 화면은 RUNNING 조회 시 명시적 join을 호출한다. 가입으로 도시 version이나 선택 원장은 증가하지 않는다.

## DB 적용·후속 작업

`001 → 002 → 003 → 004_participant_npcs.sql` 순서. 기존 DB에는 004만 한 번 적용한다. 기존 participant_sessions에 NPC ID·경로 스냅샷을 추가하고 기존 joined_at을 epoch로 사용한다. 기존 선택·결과를 재계산하지 않는다. ID·epoch·경로는 DB 트리거로 수정 금지다. 3C는 같은 가입 행에 학과를 추가할 수 있다.

- 3B: 실제 모바일/Unity 렌더러 연결, 두 기기 위치 일치·성능·복귀 검증.
- 4B: 0응답 결과 문구·결과 정책·푸시. 이번 변경은 0응답 가입/점수 저장까지이며 기존 회차의 EXCLUDE 결과 정책을 바꾸지 않는다.
- 후속 마이그레이션: 선택 5초 선마감 제거, 콘텐츠 점수 범위. 004는 기존 회차 규칙을 변경하지 않는다.
- 운영 DB 적용 및 실기기 검증은 별도이며, 격리 테스트 성공만으로 3번 전체를 완료 처리하지 않는다.

## 3B 표시 위치 보강

동시에 입장한 NPC가 같은 중심선에 겹치지 않도록 웹과 Unity가 같은 X축 차선 간격을 사용한다. NPC ID 앞 4자리의 16진수 값 `lane`에 대해 `offset_x=(lane/65535-0.5)*4m`; 보간한 중심선 좌표의 X에 더한다. 현재 직선 보행로(-67..-61m) 안에서 ±2m 범위다. 회차/기기/재접속과 무관하게 같은 ID는 같은 간격이다. 이는 화면용 충돌 완화이며 500명 밀도·혼잡 표현의 최종 규칙은 아니다.

## 2026-10 NPC 위치 동기화 (010 이후)

위 예시의 Neighborhood 경로는 이전 시제품 기록이다. 새 회차는 지도·경로 기본값이 없으며 템플릿을 복사해도 경로를 자동 복사하지 않는다. 운영자는 확정된 새 맵 인계 자료를 받은 뒤 아래 API로 **DRAFT 상태에서** 설정한다. 임의 버전이나 이전 좌표를 전시 회차에 사용하지 않는다.

`PUT /api/admin/sessions/{id}/npc-motion` — 기존 관리자 Bearer JWT와 활성 관리자 권한, 동일 출처 검사를 사용한다. 본문은 `{map_version,path_version,points,speed_mps,loop}` 경로 객체다. 버전은 영숫자로 시작하는 영숫자·마침표·밑줄·하이픈 1~128자, points는 2~2048개의 유한한 `[x,y,z]`(각 축 ±1,000,000m 이내), speed_mps는 0~100, loop는 boolean이다. 전체 경로 길이는 0보다 커야 한다. 반환은 `{session_id,motion}`. 잘못된 경로 400 `INVALID_NPC_MOTION`, 시작 후 수정 409 `NPC_MOTION_LOCKED`. 동일 본문 재요청은 같은 설정을 저장하므로 안전하다. 비밀키·관리자 토큰을 Unity/WebGL에 넣지 않는다.

입장과 첫 선택 가입은 회차 설정을 불변 `npc_motion`으로 복사한다. 미설정 회차의 신규 가입은 409 `NPC_MOTION_NOT_CONFIGURED`이고 가입·선택을 저장하지 않는다. 기존 가입은 유지되며 이전 NPC 조회 및 종료 후 재입장은 가능하다. 010은 기존 멤버의 경로를 변환하지 않는다. 이전 실행 중 회차가 미설정이면 신규 가입은 막히므로 마이그레이션은 회차 사이에 적용한다.

`GET /api/sessions/{id}/npc-positions?map_version=<빌드 지도 버전>&path_version=<선택적 경로 버전>` — 공개 익명 위치 동기화. 기존 공통 스냅샷 필드를 유지하고 top-level `map_version`, 각 NPC에 `position:{x,y,z}`, `forward:{x,y,z}`, `path_version`을 추가한다. 기존 `npc_id`, `epoch`, `motion`도 포함하므로 Unity는 한 응답으로 위치 확인과 프레임 보간을 수행한다. 참여자 신원·프로필은 포함하지 않는다. 권위 위치의 시각은 `motion_time`이다. `server_time`은 매 응답 갱신되지만 동결 후 `motion_time`과 위치는 불변이다.

필수 지도 버전 누락/형식 오류 400, 다른 지도나 요청 경로 버전 409 `NPC_MAP_MISMATCH`, 미설정 409 `NPC_MOTION_NOT_CONFIGURED`, DRAFT/없는 회차 404. 빈 군중에서도 회차 지도 버전을 검사한다. 기존 `/npc`, `/npcs`, join 응답에는 `map_version`이 추가되며 미설정·기존 회원 없음이면 null이다. 기존 회원이 있는 옛 회차는 저장된 회원 경로에서 버전을 읽는다.

위치는 경로 중심선 그대로이며 **기존 ±2m X 차선 간격을 더하지 않는다**. 웹과 Unity와 서버가 같은 계산을 한다. loop=true는 마지막→첫 점의 닫는 선분을 포함하고, false는 마지막 점에서 정지한다. 길이 0인 중간 선분은 건너뛴다. forward는 진행 방향의 단위 벡터이며 정지 상태에서는 영벡터일 수 있다. 충돌 회피·군중 분산은 확정된 맵 경로 설계에서 다룬다.

설정 순서: DB 010 적용 → 회차 생성(DRAFT) → 확정 경로 PUT → 회차 시작 → 참여자 가입 → Unity의 일치하는 map_version으로 위치 API 폴링. 운영 DB 적용과 실제 새 맵 입력은 별도 작업이다. 격리 테스트의 `test-fixture-v1`은 테스트 전용이며 운영 시드가 아니다.


## 2026-10-13 이벤트에 따른 이동 투영 (011 이후)

가입 행의 원본 경로·joined_at·NPC ID는 계속 불변이다. 응답 `epoch/motion`은 서버의 지속된 이벤트 상태를 투영하므로 유도·정지·재개 시 달라질 수 있다. `motion.revision`은 전환마다 증가하는 JS 안전 정수이며, 동일 revision 경로 변조·역행은 거부한다. `motion.freeze_at`이 있으면 NPC 보간 시 회차 freeze_at과 함께 최소 시각으로 제한한다. 활성 이벤트에서는 서버가 정지 위치를 반환하고 완료 후 현재 위치에서 원본 경로를 이어간다. 위치 이벤트는 확정된 동일 map_version 위치만 사용한다.

첫 선택의 자동 가입은 제거되었다. 입장 프로필 또는 join API로 먼저 가입하고, 서버가 발급한 본인 활성 event_id로 응답해야 한다. 기존 선택 재시도는 기존 request_key로 복원한다. 상세는 [이벤트 계약](npc-events.md) 및 web/API.md를 참고한다.
