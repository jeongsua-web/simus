# SIM:US 진행 현황 및 10월 20일 완료 일정

작성 기준: 2026-09-29 / 완료 목표: 2026-10-20(KST)

> 9/29 후속 작업: 개발 사본의 구현 기능을 본 저장소로 통합했습니다. 아래 초기 점검은 통합 전 기록이며, 최신 상태는 [통합 안내](stage4-8-integration.md)와 [검증 기록](stage4-8-validation.md)을 확인하세요. 실기기·배포와 미구현 기능 일정은 계속 유효합니다.

## 판단과 계획 전제

핵심 데이터 흐름이 구현된 연결 시제품 단계다. 전시 완성품으로 판단하기에는 개발 사본 통합, 참여자 NPC, 학과 통계, 최종 결과 연출, 외부 알림, 배포 및 실기기 검증이 남아 있다. 9월 29일부터 10월 20일까지 양 끝 날짜를 포함해 22일이다.

이 계획은 요구사항 F01~F27을 대상으로 하며, 기능 구현 마감은 10월 16일, 10월 17~19일은 현장 검증·수정, 10월 20일은 최종 인수로 잡는다. 팀 인원과 작업 가능 시간은 아직 확인되지 않았다. 서버·웹 담당과 Unity·시각화 담당이 병행하고, 콘텐츠·운영 준비를 함께 진행할 수 있다는 가정의 목표 일정이다. 1인 작업 또는 휴일 작업 불가라면 전체 범위를 같은 날짜에 완료할 수 있다고 보장할 수 없으며 9월 30일까지 범위나 인력을 조정해야 한다. 아래 담당은 확정 인명이 아닌 역할이다.

이번 점검은 저장소·소스·기존 검증 기록 검토다. 오늘 런타임 테스트를 재실행한 결과는 아니다. 완료율은 통합 범위와 인력 미확정으로 산출하지 않는다.

### 먼저 해결할 통합 문제

- `web/` + `db/` + `unity/`와 `simus-stage4-8/prototype/`는 별도 구현이다. 본 서버는 `/api/city-state`, 사본 서버는 `/api/state`를 사용하므로 사본의 테스트 통과가 본 프로젝트 전체 통과를 뜻하지 않는다.
- `simus-stage4-8/` 전체가 현재 Git에서 미추적 상태다. 필요한 소스·자산·검증 자료를 선별하고 캐시·비밀값·빌드를 제외한 뒤 버전 관리해야 한다.
- 루트 README의 Unity Editor/ProjectSettings/장면 부재 설명은 현재 파일 상태와 맞지 않는다. 통합 기준을 정한 후 문서를 최신화해야 한다.
- 제안: 본 저장소 Next.js/PostgreSQL을 기준으로 사본의 검증된 화면·Unity 연출을 이식한다. 9/30까지 실제 이식 비용을 확인하고 최종 기준을 확정한다.

## 최종 완료 체크리스트

- [ ] 실제 휴대폰 2대 이상이 QR로 참여하고 개인 선택·결과는 분리되며 도시 상태는 합산된다.
- [ ] 선택 취소/변경·중복 반영이 차단되고 응답 유실·새로고침·재접속에서 복원된다.
- [ ] 지원 기기에서 본인 NPC가 추적되고 선택 패널을 같은 도시 화면에서 사용한다.
- [ ] 모바일과 Unity의 회차·NPC·도시 상태가 일치한다. 정상 연결에서 선택→Unity 갱신 2초 목표를 측정한다.
- [ ] 학과 선택/수정 제한과 통계 분모·공개 제한이 적용된다.
- [ ] 오염 확산·도시 변화·개인 선택 피드백을 확인하고 종료 후 상태 변화가 멈춘다.
- [ ] 자동·수동 종료, 마감 경계, 무권한 요청, 반복 종료와 결과 불변을 확인한다.
- [ ] 결과에서 최종 도시·본인 캐릭터·성향을 확인하고 동의한 참여자의 외부 알림을 확인한다.
- [ ] 두 회차 연속 실행 시 초기화·과거 결과 보존·이전 회차 요청 차단을 확인한다.
- [ ] 확정된 예상 동시 접속 규모에서 부하를 검증한다. 소수 참여자 테스트를 운영 규모 통과로 간주하지 않는다.
- [ ] 전시용 빌드·HTTPS·스케줄러·백업 복원·서버 재시작 및 운영 안내를 확인한다.
- [ ] 확정 소스와 산출물을 보관하고 남은 결함·지원 기기·검증 결과를 인계한다.
