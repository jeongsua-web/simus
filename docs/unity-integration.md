# SIM:US Unity 연동 규격

확정일: 2026-09-16. 아래의 **현재 API 계약**은 저장소 코드 기준이며,
**클라이언트 처리 기준**은 후속 Unity 구현에서 적용할 정책이다. 이번 작업은 API 응답을 변경하지 않는다.

## 1. 역할과 범위

- PostgreSQL은 상태 저장, Next.js는 조회·선택 처리 API와 기존 `/participate` 참여 화면을 담당한다.
- Unity는 도시 시각화만 담당하며 `UnityWebRequest`로 `GET /api/city-state`를 조회한다.
- Unity에 DB 드라이버, `DATABASE_URL`, DB 자격 증명을 넣지 않는다. 참여자 생성·선택 제출은 기존 웹 화면을 유지한다.
- Unity 프로젝트, 렌더링 및 통신 코드는 후속 구현 범위다. `godot/`은 숨김 파일 포함 파일 목록과 Git 추적 목록을 확인했으며 현재 빈 폴더다. 삭제하지 않았고, 이후 기존 작업물이 발견되면 보존한다.

## 2. 현재 API 계약

본문·쿼리 매개변수 없이 호출한다. 인증 및 참여자 쿠키는 필요 없다. 성공은 HTTP 200,
JSON 객체이며 `Cache-Control: no-store`다. 조건부 조회, 차분 응답, 회차 지정 매개변수는 구현되어 있지 않다.

```json
{
  "city_state": {
    "session_id": "10000000-0000-0000-0000-000000000001",
    "status": "RUNNING",
    "happiness": 51,
    "safety": 50,
    "cleanliness": 54,
    "version": "1",
    "updated_at": "2026-09-16T00:00:00.000Z",
    "overall_pollution": 0,
    "regions": [
      {
        "id": "20000000-0000-0000-0000-000000000001",
        "code": "CENTER",
        "name": "중앙 구역",
        "map_metadata": {},
        "pollution": 0,
        "updated_at": "2026-09-16T00:00:00+00:00"
      }
    ]
  }
}
```

예시는 타입 설명용이며 UUID·값·지역 구성을 고정하지 않는다.

| 경로 | JSON 타입 / null 허용 | 의미 및 Unity 처리 |
| --- | --- | --- |
| `city_state` | object 또는 null | null은 조회 가능한 도시 없음. 통신 오류나 모든 지표 0을 뜻하지 않음 |
| `city_state.session_id` | string / 불가 | 회차 UUID. 회차 식별 키 |
| `city_state.status` | string / 불가 | `RUNNING`, `CLOSING`, `FINALIZED` |
| `city_state.happiness` | number / 불가 | 행복도, 0~100. 소수 허용 |
| `city_state.safety` | number / 불가 | 안전도, 0~100. 소수 허용 |
| `city_state.cleanliness` | number / 불가 | 청결도, 0~100. 소수 허용 |
| `city_state.version` | string / 불가 | 음이 아닌 PostgreSQL bigint의 10진 문자열. 아래 비교 규칙 준수 |
| `city_state.updated_at` | string / 불가 | 도시 상태 행 갱신 시각. 시간대 포함 ISO 8601 |
| `city_state.overall_pollution` | number 또는 null | 상태가 존재하는 지역의 가중 평균 오염도, 0~100. null은 집계 대상 없음 |
| `city_state.regions` | array / 불가 | 지역 목록. 빈 배열 허용. 현재 `code` 순서로 정렬 |
| `city_state.regions[].id` | string / 불가 | 지역 UUID. `(session_id, id)`로 오브젝트 식별 |
| `city_state.regions[].code` | string / 불가 | 회차 내 고유 지역 코드 |
| `city_state.regions[].name` | string / 불가 | 표시 이름 |
| `city_state.regions[].map_metadata` | object / 불가 | 임의 JSON 객체, 기본 `{}`. 좌표·모델 키 규격은 아직 없음 |
| `city_state.regions[].pollution` | number / 불가 | 지역 오염도, 0~100. 소수 허용 |
| `city_state.regions[].updated_at` | string / 불가 | 해당 지역 상태 갱신 시각. 시간대 포함 ISO 8601 |

숫자 지표는 SQL에서 `float8`로 변환되어 JSON number로 제공된다. Unity DTO는 소수를 보존하고
`overall_pollution`은 nullable 값으로 표현한다. null을 0으로 자동 변환하지 않는다.
`map_metadata` 내부에는 중첩 객체·배열·null 등 JSON 값이 올 수 있으며, 모르는 키는 무시한다.
빈 메타데이터나 미등록 지역 코드는 기본 표현을 사용하고 좌표 등을 추측하지 않는다.
시각은 UTC `Z` 또는 오프셋, 가변 소수초를 수용하는 `DateTimeOffset` 등으로 파싱한다.
도시와 지역 시각은 서로 같을 필요가 없고 요청 수신 시각·회차 종료 시각을 뜻하지 않는다.

조회는 한 SQL 문의 스냅샷으로 도시·버전·지역을 읽는다. 지역은 `session_regions`와
`region_states`의 INNER JOIN이므로 상태 행이 없는 지역은 목록에서 빠진다.
모든 지역 상태가 없으면 `regions: []`, `overall_pollution: null`이 된다.
일부만 있으면 존재하는 지역만 집계하므로 응답만으로 지역 초기화 완전성을 판단할 수 없다.

### 회차 선택과 상태

도시 상태 행이 존재하는 회차 중 `RUNNING` 또는 `CLOSING`을 우선 선택한다.
그 대상이 없으면 `finalized_at` 내림차순으로 가장 최근 `FINALIZED` 회차를 선택한다.
확정 시각이 같은 후보 간 추가 정렬 기준은 없다. 도시 상태 행 없는 활성 회차가 있어도
과거 확정 회차로 대체될 수 있다. 후보가 없으면 `{"city_state":null}`이다.

| 상태 | 표시 및 처리 |
| --- | --- |
| `DRAFT` | DB에 존재하지만 이 API에서는 반환하지 않음 |
| `RUNNING` | 진행 중 도시 표시, 폴링 유지. 선택 접수 가능 여부는 이 값만으로 판단하지 않음 |
| `CLOSING` | 종료 처리 중 표시, 마지막 도시를 표시하며 폴링 유지 |
| `FINALIZED` | 확정 상태 표시. 다음 회차 탐지를 위해 폴링 유지 |

응답에 접수 마감 시각, `accepting_choices`, 회차 이름, 개인 점수, 선택 영향값은 없다.
Unity가 타이머로 상태 전이나 종료를 추정해서는 안 된다. 관리자 시작·종료 API, 자동 종료 작업,
최종 결과 계산은 현재 API 구현 범위 밖이다. `FINALIZED` 응답도 결과 테이블이 아닌 도시·지역 상태 테이블에서 읽는다.

### version의 의미와 비교

- DB 기본값은 0이고 범위는 `0`~`9223372036854775807`이다. JSON에서는 항상 `"0"`과 같은 문자열이다.
- 현재 선택 API에서 새 선택이 성공적으로 커밋될 때 해당 회차의 버전을 1 증가시킨다. 지표가 상한·하한에 막히거나 영향이 0이어도 증가한다. 동일 요청 재실행과 롤백은 증가시키지 않는다.
- 전역 버전, 시간, API 스키마 버전, HTTP ETag가 아니다. 상태 전이·임의 DB 수정까지 포괄하는 응답 변경 번호도 아니다.
- DTO·저장·로그에서 문자열을 유지한다. `float`, `double`, JavaScript `Number`를 경유하지 않는다. 순서 비교가 필요하면 `long.TryParse`로 정확하게 비교하거나, 정규 10진 문자열의 길이와 동일 길이의 사전순으로 비교한다.
- **먼저 `session_id`를 비교한다.** 다른 회차의 버전끼리는 비교하지 않는다. 새 회차의 `"0"`은 이전 회차의 높은 버전보다 오래된 응답이 아니다.
- 같은 회차에서 동일 버전이어도 `status`와 전체 스냅샷을 확인·반영한다. 무거운 시각 갱신은 관련 값까지 동일할 때만 생략한다.
- 같은 회차에서 버전이 감소하면 자동 덮어쓰기를 거부하고 데이터 불일치로 기록하여 재조회한다. 의도적인 DB 복원이라면 운영 확인 후 클라이언트 기준 상태를 명시적으로 초기화한다.
- 버전이 여러 단계 증가해도 최신 스냅샷으로 바로 동기화한다. 누락된 선택 이벤트를 복원하거나 중간 값을 실제 사건처럼 재생하지 않는다.

## 3. 클라이언트 처리 기준

아래 시간은 서버의 보장값이 아니라 이번에 정한 Unity 기본 설정이다. 게임 배속·일시정지에
영향받지 않는 실제 경과 시간 기준으로 구현하고, 설정으로 변경 가능하게 한다.

| 항목 | 기본 기준 |
| --- | --- |
| 시작·재활성화 | 즉시 1회 조회. 대기 중 요청은 최대 1개 |
| 정상 폴링 | 유효 응답 처리 완료 후 2초 뒤 다음 요청. null·FINALIZED에서도 유지 |
| 요청 타임아웃 | 요청 시작부터 10초. 시간 초과 시 취소하고 실패 처리 |
| 일시 오류 재시도 | 실패 완료 후 2 → 4 → 8 → 16 → 30초, 이후 30초 상한. 각 대기에 ±20% 지터 적용 |
| 복구 | 유효한 HTTP 200 응답(null 포함)을 받으면 실패 횟수를 초기화하고 2초 폴링 복귀 |
| 연결 상태 | 첫 실패는 재연결 중 표시. 마지막 유효 응답 이후 15초 경과 시 연결 끊김 표시. 아직 성공이 없으면 시작 시각을 기준으로 적용 |
| 비활성화·종료 | 진행 요청 취소, 예약 폴링 정리. 복귀 시 즉시 조회하며 누적 요청을 몰아서 보내지 않음 |

재시도 대상은 네트워크·DNS·TLS 오류, 타임아웃, HTTP 408/429/5xx,
JSON 파싱 실패 및 계약 위반이다. 429/503에 유효한 `Retry-After`가 있으면 지터 적용 대기와
서버 지정 대기 중 더 긴 시간을 지킨다. 그 외 4xx는 주소·설정 오류로 표시하고 자동 재시도를
멈춘다. 설정 수정 또는 명시적 재연결로 재개한다. CORS 오류는 브라우저에서 일반 네트워크
실패처럼 보일 수 있으므로 브라우저 콘솔도 확인한다.

현재 서버의 내부 오류는 HTTP 500과 다음 JSON이다. 프록시·브라우저 실패가 같은 JSON을
반환한다고 가정하지 않고 HTTP 상태와 본문을 각각 검사한다.

```json
{"error":{"code":"INTERNAL_ERROR","message":"요청 처리에 실패했습니다."}}
```

실패 시 마지막 정상 도시를 유지하고 오래된 데이터임을 표시한다. 최초 조회 전에는 로딩 또는
연결 대기 화면을 표시한다. 지표를 0으로 바꾸거나 가짜 변화를 만들지 않는다. 15초 판정은
`updated_at`이 아닌 유효 응답 수신 시각으로 한다. 변화 없는 도시도 정상 연결일 수 있다.
브라우저 백그라운드에서는 실행이 지연될 수 있으므로 복귀 즉시 경과 시간을 재평가한다.

### 응답 적용 순서

1. 취소·타임아웃·이전 활성화 세대의 늦은 응답을 폐기한다. 단일 요청 원칙과 요청 세대 번호로 오래된 응답의 적용을 막는다.
2. HTTP 상태와 JSON을 검사한다. 필수 필드 누락, 허용되지 않은 null·타입, 미지의 상태, 범위 밖 지표, 잘못된 버전은 계약 오류로 처리하고 마지막 정상 상태를 유지한다. 추가된 미지 필드는 무시한다.
3. `city_state: null`이면 정상적인 빈 상태로 처리한다. 이전 도시·지역·버전·진행 애니메이션을 비우고 “표시할 회차 없음”을 표시한다. 연결 끊김과 구분한다.
4. 첫 도시 또는 `session_id` 변경이면 이전 지역 오브젝트·버전 캐시·보간을 초기화한 뒤 새 전체 스냅샷을 적용한다. 다른 회차 사이를 보간하지 않는다. API 선택에 따른 과거 확정 회차로의 변경도 동일하게 처리한다.
5. 같은 회차면 버전 감소를 검사하고, 감소가 없으면 상태와 도시·지역을 한 번에 적용한다. 목록에서 사라진 지역은 제거하고 새 지역은 생성한다. 배열 위치가 아닌 지역 ID로 대응한다. 빈 배열은 지역을 비우고 null 집계는 “집계 없음”으로 표시한다.
6. 연결 상태와 수신 시각을 갱신한다. 보간을 사용하더라도 서버의 목표값을 보존하며 새 응답 수신 시 최신 값으로 목표를 교체한다.

## 4. 주소와 출처

| 실행 환경 | API 주소 기준 | 제약 |
| --- | --- | --- |
| Unity Editor·데스크톱, 서버와 같은 PC | `http://localhost:3000/api/city-state` | 브라우저 CORS 적용 대상 아님. 개발용 HTTP 사용 가능 여부는 Unity 프로젝트 설정 확인 |
| Unity Editor·데스크톱, 다른 PC | `http://<서버 LAN IP>:3000/api/city-state` 또는 운영 HTTPS URL | localhost는 실행 PC 자신. 서버 바인딩·포트·방화벽 접근 필요 |
| WebGL 로컬 | 페이지 출처가 `http://localhost:3000`이고 API도 같은 출처 | 별도 개발 서버의 포트가 다르면 다른 출처. 같은 출처로 정적 파일을 제공하거나 프록시 필요 |
| WebGL 운영 | 예: 페이지 `https://simus.example/unity/`, API `https://simus.example/api/city-state` | 페이지 출처 기준 루트 `/api/city-state`를 절대 URL로 구성. `/unity/api/city-state`로 붙이지 않음 |

네이티브의 API base URL은 환경별 설정으로 주입한다. Compose의 `db:5432`는 컨테이너 내부
DB 주소이며 Unity API 주소가 아니다. `web:3000`도 호스트 클라이언트 주소로 사용하지 않는다.

WebGL의 `UnityWebRequest`는 브라우저 네트워킹과 CORS 제약을 따른다.
근거: [Unity 공식 Web networking 문서](https://docs.unity.cn/6000.0/Documentation/Manual/webgl-networking.html).
동일 출처는 **스킴·호스트·포트가 모두 같음**을 뜻한다. `localhost`와 `127.0.0.1`,
서로 다른 서브도메인, 3000과 다른 포트는 같은 출처가 아니다.

현재 GET 핸들러는 `checkOrigin`을 호출하지 않지만 CORS 허용 헤더도 제공하지 않는다.
그러므로 GET이 서버에 도달하는 것과 다른 출처 WebGL이 응답을 읽는 것은 별개다.
이번 배포 기준은 동일 출처이며, 정적 호스팅이 분리되어 있다면 공개 출처의 `/api/`를
Next.js로 전달하는 리버스 프록시를 별도로 구성한다. 이는 현재 저장소에 구현된 설정이 아니다.
다른 출처 직접 호출을 허용하려면 후속 서버 CORS 검토가 필요하며 이번에는 추가하지 않는다.

운영은 페이지와 API 모두 HTTPS로 제공한다. HTTPS 페이지에서 HTTP API 호출은 혼합 콘텐츠
제약을 받으므로 사용하지 않는다. WebGL을 `file://`로 열지 말고 HTTP(S) 서버로 제공한다.
공개 WebGL에 localhost API 주소를 넣으면 방문자 자신의 PC를 가리키므로 사용하지 않는다.

## 5. 후속 구현 검증 항목

- 실제 GET으로 전체 필드와 소수 지표를 읽고 참여 화면의 선택 이후 최신 도시를 표시한다.
- `city_state: null`, 빈 지역 배열, null 집계, `{}` 메타데이터를 각각 정상 처리한다.
- `"9007199254740992"`와 `"9007199254740993"`, bigint 최댓값을 문자열 그대로 보존·구분한다.
- 동일 버전의 RUNNING → CLOSING → FINALIZED, 높은 버전의 이전 회차 → 버전 0 새 회차를 검증한다.
- 버전 건너뜀·감소, 지역 추가·제거, 늦게 도착한 취소 요청을 검증한다.
- 10초 타임아웃, 15초 연결 끊김, 재시도 간격·복구, 오류 본문이 JSON이 아닌 경우를 검증한다.
- Editor·데스크톱과 동일 출처 WebGL에서 각각 확인한다. 다른 출처 WebGL 차단도 확인한다.
- DTO가 null·필드 누락을 기본 숫자 0으로 숨기지 않는지 검증한다. 아직 Unity 구현이 없으므로 이 목록은 미실행 상태다.
