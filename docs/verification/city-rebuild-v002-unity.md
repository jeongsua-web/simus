# City rebuild v002 — Unity implementation, phases 1–3

Scope: the user approved the existing v002 design and requested implementation through Phase 3, followed by personal Unity inspection. This work does not implement Phases 4–7. Generated evidence is `city-rebuild-v002-unity-results.json`; final execution status is recorded there only after the Unity generation method completes successfully.

## Input and implementation

- Approved placement source: `docs/planning/city_rebuild_v002/layout.json`; 55 external building placements and 14 campus components, with `buildings.csv` and `campus-placements.csv` independently checked by QA. The v001 2×2 map is excluded.
- Reused evidence: the 2026-10-13 Blender/Unity investigation, the v002 design QA checker and the read-only Blender FBX audit/name map. Campus FBX contains 487 meshes; source-to-FBX mapping avoids guessing sanitized Korean object names.
- New assembler: `unity/Assets/Editor/CityRebuildV002Setup.cs`, executed in Unity by `CityRebuildV002Setup.Build`. New scene: `unity/Assets/SIMUS/Scenes/city_rebuild_v002/CityRebuild_v002.unity`. Protected original scene and build settings are compared byte-for-byte by the assembler.
- Geometry: mitered polyline carriageways, separately owned intersection asphalt, circular turning heads or rectangular delivery pads, raised pedestrian surfaces and the 17 approved crossing facility groups. Convex clipping removes same-height road, walkway and marking double coverage. Road widths and pedestrian widths come directly from v002. The graph is used for physical surface generation; it is not activated as an NPC route system.
- Actual model placement: all 55 external buildings use existing FBX prefab instances; campus buildings use the exact 308 constituent meshes from existing Campus.fbx, with FBX mesh/material GUID references. Campus original world geometry is retained under instance wrappers; C00, C02, C08 and C09 receive their approved deltas. Actual Unity imported and world bounds are compared with the measured design envelopes. No building proxy replaces a model.
- Original campus surface/plinth, sports field, field lawn, basketball and tennis meshes/markings plus existing garden ground pieces are selected from actual FBX. The legacy campus road/walk meshes, legacy tree decoration and old field edge lines are excluded from this phase. East park modules/props belong to Phase 4; only designed park trail surfaces are present now.

## Known entrance and camera limitations

Blender inspection identifies provisional external entrance directions that disagree with actual models: House 01/02/03 Entry Ramp is on +Z; Villa 01/02 access and Apartment A Entry Glass are on +X. The approved yaw/positions remain intact, while planned exterior anchors remain visibly reviewable. A building-envelope pass does not certify access through a real door or over a threshold.

The original camera script is unchanged. Its new-scene overview size is 260 and top-view size 235 for static inspection of the 420×435 m extent; follow size/pitch/yaw remain the copied values. The original runtime Update clamps the internal zoom to 170 while controls are enabled, so city-wide framing is a known Phase 6 issue. The results JSON records scene-specific before/after camera parameters. Runtime tracking, dynamic apartment occlusion and screen readability are NOT TESTED in this scope.

The copied NPC model/controller and `TestNpcPatrol`/`NpcGrounding` remain present. Its short local campus segment is a visual inspection aid, not a connected 388-node/409-edge route implementation. NavMesh, full NPC movement, event logic and population performance tests (1/100/500/1,000 NPCs) remain NOT TESTED. No backend, database or web code is changed.

## Executed Unity generation and corrected implementation issues

Unity 6000.3.24f1 completed FBX import/compilation and `CityRebuildV002Setup.Build` with exit 0 (`/tmp/simus-v002-build-retry.log`), generated 539 mesh assets, placed all 69 building wrappers, saved the scene and reopened it. The generated report verified the original source scene/build selection remained byte-identical during this run. The independent Unity probe confirmed the FBX source-axis contract `(U.X,U.Y,U.Z)=(-B.X,B.Z,-B.Y)`; the assembler corrects this with a 180° child/root adapter before applying the approved positions and yaw. Campus aggregate envelope calibration error was 0.012387 m across the 14 components.

The first generation attempt failed on a long window-frame name: Blender's importer had shortened and rehashed 14 long names, while Unity preserved raw FBX names. Blender's raw name mapping and the 487-renderer Unity import probe resolved the mismatch without changing a source FBX or `.blend`. Rectangular delivery turn pads are handled separately from radius-based turning heads.

The first static top-view render revealed an uncovered area where the true campus surface silhouette differed from its rectangular AABB. The final generator places continuous city ground at Y=−0.02 m beneath the original campus surface instead of deleting the AABB area. The initial static NPC inspection render showed unsampled bind-pose geometry; the capture method now manually samples the existing `NEUTRAL_WALK` clip at 0.5 seconds. Both are editor inspection corrections and do not constitute Play Mode validation.

A separate `CityRebuildV002SurfaceAudit.Run` loads the saved scene, samples every one of the 409 physical graph edge centre-lines at ≤1 m intervals, raycasts actual Unity colliders, and reports supported samples and building collider hits. Results are written to `city-rebuild-v002-surface-audit.json`, with the actual saved scene SHA. It verifies physical surfaces only; NPC radius, kerb stepping, real doorway gaps, graph movement and NavMesh remain outside this test. Final regenerated/captured/audited run results and exit status are reported by the coordinator and independent QA.

### Final Phase 3 generation and collider results

The final generator run exited 0 in `/tmp/simus-v002-build-verified.log`. It serialized **560 generated meshes**, 69 actual FBX building placements, and 25 retained campus facility meshes, saved and reopened the new scene. The source script SHA in the execution JSON matches the final generator file.

The saved-scene surface audit exited 0 in `/tmp/simus-v002-surface-verified.log`: **10,517 centre-line samples, 0 missing generated-road/path support, 0 sampled building-collider hits** across all 409 edges. This is a Unity Editor physics result. It does not replace actual NPC traversal or finite-radius NavMesh/door/kerb checks. Earlier missing samples were traced to crossing-labelled edges that extended beyond asphalt; their outside-road portions are now constructed as raised approach surfaces while preserving the approved carriageway widths. Small polygon area calculations now use origin-relative double accumulation to preserve sub-millimetre endcap fragments.

The independent serialized-triangle checker additionally samples the centre and ±45% finite width of roads/walkways. Its final result and physical-distance boundary tolerance are owned by QA and recorded separately in `city-rebuild-v002-surface-results.json`.
