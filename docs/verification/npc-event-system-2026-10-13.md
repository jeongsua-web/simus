# NPC 위치 기반 이벤트 전환 검증 (2026-10-13)

## 구현 결과

기존 접속 즉시 설문 선택지를 표시하던 흐름을 서버가 결정하는 이벤트 흐름으로 변경했다. backend, database, unity, web-ui, qa 역할별 에이전트를 활용했다. 기존 선택 결과 스탯, 원장 멱등성, 시민 프로필, 학과 통계, 관리자 회차 운영, 결과 공유 및 푸시 기능은 유지했다.

- 서버의 NPC 이동 경로와 승인된 이벤트 위치를 비교하여 위치 이벤트를 발생시킨다.
- 대기 60초부터 가까운 이벤트 위치로 이동을 유도한다. 대기 90초가 지나면 현재 위치에 맞는 이벤트 또는 공통 이벤트를 발생시킨다.
- Node 서버의 250ms 주기 처리로 브라우저 접속 없이 진행한다. 실제 시작 시각은 처리 시각이며 90초 deadline과 별도로 저장한다.
- 참여자별 진행 이벤트는 최대 하나이다. 이벤트 중 이동을 멈추고 완료 시 이동과 대기 타이머를 재개한다.
- 선택 제출은 참여 자격, 회차 상태, 본인 이벤트 소유권과 상황 일치 여부를 서버에서 검증한다. 중복 요청의 점수 반영은 한 번이다.
- UI는 ACTIVE 이벤트의 선택지만 표시하며 대기, 유도, 종료 및 조회 실패 시 선택지를 숨긴다.
- 이벤트 좌표는 DRAFT 회차에서 관리자만 설정할 수 있다. 새 전시 지도 좌표를 임의로 만들지 않았다. 위치 설정 전에도 새 회차 시작 시 중립적 공통 이벤트가 준비된다.

## 검증

격리된 임시 PostgreSQL과 서버에서 전체 API 통합 검사를 통과했다. 기존 스탯/원장/회차/프로필/학과/결과/콘텐츠 검사와 다음 이벤트 검사를 포함한다.

- 59/61/89/91초 경계, 브라우저 없이 발생, 서버 재시작 이후 유지
- 동시 조회와 선택, 다른 참여자의 이벤트 거부, 위조 이벤트 거부, 완료 후 타이머 초기화
- 위치 이벤트 우선, 공통 이벤트 재사용, 이동 정지와 연속적인 재개
- 1,000명 기한 초과 참여자의 자동 이벤트 발생
- 모바일 브라우저 대기/선택/제출/재접속, 통신 실패 재시도 및 이미 저장된 응답 복구
- 360/390/430px 및 글자 확대, 선택 패널 접근성 및 화면 넘침 검사

웹 production build 통과. lint 오류 없음(기존 결과 공유 화면 경고 1건). 웹/Unity 브리지 Node 검사 6건 통과.

Unity EditMode 실행은 설치된 Unity의 라이선스 초기화에서 진행되지 않아 결과를 얻지 못했다. C# 변경과 EditMode 테스트 소스는 포함되지만 Unity 컴파일/실제 WebGL 렌더 검증 및 새 WebGL 빌드는 완료되지 않았다. 격리 브라우저에서는 선택 UI를 검사했고 기존 WebGL 산출물은 사용하지 않았다.

에셋 카탈로그 검사는 원본 저장소의 기존 누락 Blender 파일, 해시 불일치 및 오래된 inventory 때문에 실패했다. 이번 변경은 에셋을 수정하지 않았다.

## 운영 적용 순서

1. 진행 회차가 끝난 뒤 배포한다. 운영 데이터베이스는 이번 검사에서 변경하지 않았다.
2. `db/011_npc_events.sql`을 앞선 마이그레이션 뒤에 적용하고 `db/verify_schema.sql`로 확인한다.
3. 웹을 빌드하고 지속 실행되는 Node 서버로 배포한다. 서버리스 요청 실행만으로는 주기 처리의 시간 보장이 성립하지 않는다.
4. DRAFT 회차에 현재 지도 버전의 승인된 위치/반경을 관리자 이벤트 위치 API로 등록한다. 계약은 `docs/contracts/npc-events.md` 및 `web/API.md` 참조.
5. Unity 라이선스 문제를 해결하고 EditMode 검사를 실행한 뒤 WebGL을 다시 빌드한다. 구버전 WebGL로 이동 유도/정지/재개 전체 동작을 검증했다고 간주하면 안 된다.
6. 새 회차로 입장 → 대기 → 유도 → 이벤트 → 응답 → 재대기 흐름을 실제 전시 환경에서 확인한다.
