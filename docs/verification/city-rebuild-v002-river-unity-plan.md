# CityRebuild_v002 Phase 4 하천 — Unity 설계·구현 근거

2026-10-16. 설계 보고 후 기존 작업 씬에 증분 적용했다. 기준은 `docs/planning/city_rebuild_v002/layout.json`과 `river-design.json`이다. 이전 Neighborhood 좌표나 모델은 사용하지 않았으며 전시 `map_version`은 확정하지 않았다.

## 위치와 간섭 검토

동쪽 공원 내부 중심선을 `(127,-12) → (122,15) → (118,45) → (118,75) → (120,104) → (120,125) → (133,155)`로 배치했다. Catmull–Rom 곡선 약 170.67m, 수면 폭 10m, 전체 하천·둔치·양안 보행로 폭 24m다. 설계 검토는 약 0.3m 샘플, 실제 로우폴리 메시 단면은 약 2m 간격으로 구분한다.

설계 중심선과 전체 반폭 12m 기준 공원 경계 여유 2.20m, 차도·보도 여유 21.38m, 건물 envelope 여유 22.76m를 확보했다. PM1/PM2 공원 모듈 여유는 각각 약 0.48/3.56m다. PM1 근처는 폭을 넓힐 여유가 작다. 수면을 12m로 넓히면 PKE01 유효 보행 폭과 겹치므로 현재 구현은 10m로 고정했다.

기존 공원 순환로 PKE02와 PKE07의 XZ 경로를 보행교로 유지한다. 북측 길이 약 28.694m, 남측 약 32.092m이며 난간 안쪽 유효 폭 3m, deck Y=0.14m다. 기존 보행로와 새 둔치 길이 접속하는 위치에서 난간 모듈을 제외한다. PM1/PM2와 모든 건물·도로는 유지하며, 굴착 영역에 걸리는 기존 나무 12개는 원래 오브젝트를 보존한 채 비활성화했다.

## 실제 지면 단면

CityGround와 EastPark_Lawn의 렌더러·Collider 양쪽 메시에서 실제 하천 구간을 잘라낸다. 별도의 하상, 사면, 둔치, 산책로, 폐합하는 반원형 끝 지형을 생성한다. 수면에는 Collider를 붙이지 않는다. 원본/Phase 4 메시 파일은 변경하지 않고 씬 전용 `river_meshes` 파생 메시를 사용한다.

새 둔치 산책로는 기존 보행로 및 보행교와 만나는 구간에서 12m의 접근 길이를 두고 Y=0.14m까지 올라간다. 이로써 기존 높은 길과 새 낮은 길이 수직으로 겹치지 않는다. 지면 아래에 묻혔던 대각선 진입 램프는 제거하고, 이 높이 전이의 정상부에서 다리 끝으로 연결한다. 독립 QA가 계산한 실제 산책로 최대 경사는 4.686%다.

차집합 메시 생성 과정에서 생길 수 있는 매우 가느다란 삼각형은 `삼각형의 두 배 면적 / 최장변 < 0.1mm` 기준으로 제거한다. 최초 강화 검사의 CityGround capsule 충돌은 길이 16m·높이 약 7µm인 절개 경계 잔여 삼각형에서 재현됐으며, 최종 메시에는 해당 잔여가 없다. Collider에는 갱신된 메시를 강제로 다시 할당해 재조리한다.

## 보행 연결과 물 진입 금지

원본 388 nodes / 409 edges JSON은 유지하고 씬 직렬화 그래프에 양안·보행교·접속 경로를 추가했다. 최종 씬은 572 nodes / 597 edges다. 기존 `TestNpcPatrol`과 `NpcGrounding`을 사용한다. NavMesh 패키지나 베이크는 도입하지 않았다.

Transform 기반 MoveTowards 이동에는 장애물 Collider만으로 물 진입을 막을 수 없다. `CityV002RiverGuard`가 매 프레임 이전 위치에서 새 위치까지의 선분을 0.2m 간격으로 확인하고, NPC 반경을 포함한 물 영역 진입을 되돌린다. 보행교는 실제 deck 근처 높이와 폭을 동시에 만족할 때만 허용한다. 물속에서 다리 아래 XZ 영역을 통과하는 경우는 허용하지 않는다. 그래프 이동을 다시 시작할 때도 시작 위치 안전 여부를 검사해 guard 위치를 갱신한다.

기존 Phase 4 공원 재생성 메뉴는 하천이 있는 씬에서 명시적으로 중단한다. 기존 Phase 5 그래프 재생성은 직렬화한 하천 확장과 하천 probe의 그래프 참조를 다시 연결한다. 이 재적용 경로의 실제 실행 검사는 별도로 기록해야 한다.

## 에셋·수질·검증

북측/남측 deck와 반복형 난간·끝 기둥은 Blender에서 제작한 `river_footbridge_v001` 실제 FBX를 사용한다. Unity native bounds는 북측 3.4×0.400003×28.699999m, 남측 3.4×0.400004×32.099995m, 난간 0.16×1.1×2m로 확인했다. 별도의 단순 메시·Box Collider가 물리 역할을 맡고 해당 renderer는 비활성화한다.

수면의 `CityV002RiverWater`는 0–100 도시 오염도를 MaterialPropertyBlock 색·매끄러움으로 반영한다. 기존 공용 머티리얼 파일과 지역 매핑은 변경하지 않는다. 실시간 도시 aggregate나 Inspector 오염도 입력을 사용할 수 있다.

최종 Apply의 실행 증거는 `city-rebuild-v002-river-unity-results.json`, 로그는 `/tmp/simus-v002-river-apply-final.log`다. 실제 Unity Editor 물리 검사에서 중심선 35,489개, 유효 폭 7,461개 표본의 물 침범·지지 누락·반경 0.2m capsule 충돌은 모두 0이다. 물 위 그래프 표본에서 실제 보행교 Collider hit 665개를 확인했다. 하천 중심 86개 표본의 하상 누락과 물 아래 기존 평면 잔존도 0이다.

이 문서의 Apply 검사는 Play Mode 왕복 이동이나 캡처 결과를 대신하지 않는다. 런타임·EditMode 테스트·화면 검증의 최종 상태는 메인 검증 보고서와 해당 실행 JSON에서 확인한다.
